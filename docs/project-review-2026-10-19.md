# 工程梳理与优化记录（2026-10-19）

本轮优先处理回复可靠性、轮次中断和任务查询，再清理文档中的旧角色说明。浮灵仍是唯一正式角色；启动命令保持 `npm run start` 同时启动、`start:claw` 只启动服务、`start:pet` 只启动桌宠。

## 已完成的代码调整

| 问题 | 调整后的行为 | 主要位置 |
| --- | --- | --- |
| 收件标记完成与回复入队分开写入，崩溃窗口可能丢失回复 | 同一 SQLite 事务写入终态及最终回复，再尝试投递 | `src/storage.ts`、`src/app/outbox.ts`、`src/app/application.ts` |
| 桌面连接写入成功不等于界面已保存，断线时可能丢失或重复回复 | 发件表保存稳定投递 ID；新版界面先持久化成功文本、记录收据再确认；重连重投按 ID 去重 | `src/desktop/gateway.ts`、通道接口、`desktop/src/app.py`、`desktop/src/storage/chat_store.py`、`desktop/src/protocols/protocol_v1.py` |
| 文本写入中断留下不完整 JSONL 行，可能影响后续历史读取 | 写入后刷新到磁盘，追加前隔开残缺尾行；加载时跳过损坏行；索引失败不撤销已保存文本 | `desktop/src/storage/chat_store.py` |
| 停止或超时后过早释放活动轮次，旧轮次仍可能继续执行 | 等待完成事件或断线后释放；启动尚未返回 ID 时先记停止状态，取得 ID 后补中断；占位期间拒绝开启新轮次 | `src/codex/runtime.ts`、`src/codex/rpc.ts` |
| 后台任务先全部读取再筛选，任务增加后开销增大 | 按状态、聊天及创建时间建立索引，使用有界 SQL 查询 | `src/storage.ts`、`src/services/jobs.ts` |

桌面保存确认只覆盖最终文本。流式进度、附件、图片及语音播放不在该确认契约内；失败或会话重置终态保存收据，但不伪造一条成功的助理回复。旧桌宠不支持确认时会触发重试，需要服务与界面一起升级。清空界面历史保留投递收据，避免未完成投递把已经清除的回复再次写回。

发件重试最多八次，失败后可通过 `/retry` 重投；ID 在重试过程中保持不变。飞书仍不具备端到端去重保证。取消不能撤回已经完成的外部操作；若服务端没有返回任何轮次状态，停止占位可能需要重连或重启才能解除。

## 验证与剩余工作

本轮遵守工程约定，不新增或运行测试。`npm run check`、`npm run build` 和本轮修改的三个 Python 文件语法检查均已通过。尚未运行真实登录会话、桌宠界面联调或现有数据库迁移，不能据此认定端到端验收完成。

尚未实跑：旧业务数据库迁移、断线后最终回复重投、桌宠保存失败后的恢复、模型启动与停止竞态、飞书回调及真人授权全链路。代码与静态检查不能替代这些运行验收。

下一步优先进行一次受控的服务与桌宠联调，覆盖发送、停止、重连和恢复；随后核对一条由 gpt-claw 创建的原生线程能否在 ChatGPT 桌面端找到。跨 DPI 指示定位、浮灵动作过渡与运行性能仍按[浮灵运行时说明](minipet-spirit-runtime.md)及[交互方案](minipet-interaction-design.md)验收。数据库版本迁移、备份与保留策略仍是后续工程项。
