# gpt-claw 专属宠物交互方案

状态：2026-10-22，部分落地。浮灵已成为唯一正式角色，目标标记、单只宠物移动避让、目光与手臂示意、到时归位及撤销已接入代码；入口见[浮灵运行时说明](minipet-spirit-runtime.md)。猫耳模型已备份，旧图片角色与加载入口已撤下。本轮已接入双击轻聊天、同窗展开完整记录、双按钮悬停入口、分层右键菜单和固定进度条。局部 Qt 预览不代表真实对话到桌面的完整链路验收。卡片与聊天窗口整合、精确跳行和周期 AI 主动陪伴仍属于后续工作；文末 HTML 示例不是实际操作证据。

## 产品定位

桌宠是 gpt-claw 的专属宠物，跟随用户工作并承担桌面交互。用户可以和它聊天，让它解释当前内容、指出位置、操作窗口，也可以让它阅读工程文件、说明代码问题并跳到对应行。宠物形象、对话面板、屏幕标记和实际执行共同表达同一件事。

Codex 继续作为唯一执行内核；界面不另建模型会话。默认按用户请求观察；用户另行开启“主动陪伴”后，才允许稀疏的周期观察与模型判断，不默认录屏。本地界面连续驱动动画和位置标记，模型只决定有意义的行为意图。

角色与整体体验见 [桌宠角色与助手整体设计](minipet-character-design.md)。最新决定是“一个本体、一套桌面标记、一个可展开的对话面板”，第一版不做独立分身。本体平时有散步、玩耍、发呆和休息等日常；在持续阅读或操作时可移动到软件边缘，标记负责准确指出位置。主动陪伴开启后可以适时到工作窗口旁询问是否需要帮助，用户忽略后恢复日常，不反复追问。

## 当前鼠标交互

| 操作 | 行为 |
| --- | --- |
| 悬停浮灵 | 停留至少 550 毫秒后显示“聊天 / 语音”，不抢输入焦点；系统双击间隔较长时相应延后 |
| 单击浮灵 | 保留触摸回应；睡着时可唤醒 |
| 双击浮灵 | 打开身旁的轻聊天，显示最近 6 条消息与输入框；点击“完整记录”在同一窗口展开 |
| 拖动浮灵 | 移动宠物，取消本次触摸与悬停入口 |
| 单次右键 | 打开聊天、陪伴方式、协助我、设置和退出；动作、语音和共享屏幕放在对应子菜单 |
| 双击回复卡片空白或标题 | 展开原有快捷输入，继续当前对话 |

悬停入口采用深紫底、冰青强调色和短淡入；聊天窗口采用浅紫阅读区与固定的冰青状态条，思考进度不写入正文。陪伴方式保留“安静陪伴 / 日常陪伴 / 活泼一点”，另有随状态切换的“睡觉 / 叫醒”，动作收进子菜单；这些选择只调整本地行为，不自动发起模型请求或共享屏幕。

轻聊天默认 400×460，完整记录默认 600×680，最小 340×360 个逻辑像素。轻聊天从宠物旁边展开，边缘空间不足时换侧，窗口尺寸和位置按可用屏幕调整。关闭只收起窗口，保留草稿及进行中的回复；最小化后重新打开会恢复窗口。当前记录仍由原有 ChatStore 与 Codex 线程绑定管理。

打开聊天时浮灵短暂看向面板，输入时目光跟随输入区，收起时轻轻挥手。聊天展开期间暂停随机日常活动；已有任务、专注或休息状态优先，这些小回应不会排队补播，也不调用模型。

本轮使用实际 Qt 控件完成隐藏渲染，覆盖轻聊天、完整记录、最小尺寸、悬停入口、右键菜单和长文本换行。三种尺寸均无页面横向溢出，最小尺寸下输入区与发送按钮可见。8 条示例消息在轻聊天中显示最近 6 条，展开后显示全部；关闭后草稿仍在，模拟的流式回复回调可以继续接收并在重开后显示。预览与尺寸记录保存在工程忽略目录 `data/development/pet-interaction-20261022/`，其中 `interaction-preview.png` 是控件拼图，`render-metrics.json` 是页面测量结果。本次未操作真实桌面，实体鼠标手势、不同 DPI、浮灵回应动画和真实模型对话链路仍需运行验收。

## 面板形态与后续整合

轻聊天与完整记录已复用同一窗口。回复卡片和快捷输入仍保留，统一为一个面板是后续工作：

| 形态 | 何时出现 | 展示什么 | 如何退出 |
| --- | --- | --- | --- |
| 陪伴 | 平时、用户主动收起后 | 宠物；有新回复时显示简短气泡 | 双击宠物打开轻聊天；双击卡片展开快捷输入 |
| 对话 | 用户打开、发送消息、任务需要用户决定 | 最近对话、文字输入区、必要的任务反馈 | 主动收起；草稿、对话和进行中的任务保留 |
| 阅读 | 用户展开长回答、代码或历史 | 同一段对话加宽，按需查看记录 | 缩回对话大小或收起 |

当前对话宽 400 个逻辑像素，阅读宽 600；窗口记住两种形态各自调整后的大小，长内容在消息区滚动。靠近屏幕边缘时向另一侧展开。

后续将卡片作为面板的收起形态，统一回复卡片、快捷输入、聊天窗口的内容与入口，复用现有消息渲染和 ReplyCoordinator，避免同一回复出现多个独立窗口。已有历史可按需展开，不常驻侧栏。

鼠标经过可以提示，但不直接展开大窗口。点击打开后保持展开；阅读、选中文字、输入、等待确认期间不因移开鼠标而关闭。正式回答不自动消失；欢迎、再见等短提示可以定时收起。忙碌时不抢焦点；收起后宠物用小标记提示进展，只有必要的用户决策才提示打开。

## 信息层级

固定状态条已接入实际进度事件；以下完整信息层级及入口整合仍是后续目标：

1. 顶栏只保留头像与名称、记录、阅读大小、收起。配置与不常用功能进入宠物菜单。
2. 正文只放对话结果、图片、文件和真正有用的操作入口。普通聊天、欢迎和结束语不显示“已完成”。
3. 活动条只在有实际状态时出现，例如“正在看编辑器”“正在打开设置”“正在听你说”“等待确认”；执行期间有停止入口。最后一步不能凭本地计时器冒充成功。
4. 过程折叠展示工具记录、耗时和消耗；正文下面不常驻一排 Token、时间、统计。任务结束后回到普通消息。
5. 输入区统一文字、现有语音和附件入口，并放共享屏幕开关。不开共享时就是普通对话。

框选文字后复制、双击卡片进入输入继续保留。底部不恢复重复的“复制”“追问”。上下文按钮必须能完成具体动作，例如“打开第 42 行”“指给我看”“打开文件”，只在对应结果存在时出现，不给每条消息配固定工具栏。

“收起”只改变显示；“停止”取消当前任务；“关闭共享”撤回屏幕能力。三者不能共用一个模糊的关闭按钮。停止后以服务取消结果为准；失败、连接中断都明确展示实际情况。

## 屏幕阅读、指路与操作

| 用户想做的事 | 助手行为 | 可见反馈 |
| --- | --- | --- |
| “这段讲什么？” | 按需截取目标窗口并解释 | 最近观察的窗口名称、正文解释 |
| “设置在哪里？” | 截图定位，返回位置标记 | 目标处短暂高亮与简短提示，不移动或点击鼠标 |
| “帮我打开设置” | 按现有 computer 工具操作，操作后再截图检查 | 当前一步和停止按钮；成功后给出实际结果 |

无需永久切换“聊天 / 看屏幕 / 操作”模式。用户通过自然语言表达目的，共享状态决定屏幕工具是否可用；必要时助手澄清目标。

共享默认关闭，不持久化到下一次启动。开启本身不发送模型消息、不截图、不启动循环观察。当前实现的共享授权包含操作能力，因此开关要明确写“共享中 · 可操作”。“只看”若后续加入，必须在后端真正拒绝点击、输入、拖动等动作，不能只改标签。

显示“最近查看：应用名称”，不要把旧截图伪装成实时画面；实际操作期间才显示“正在操作：应用名称”。共享关闭、断线、换会话、退出后撤回能力。继续保留 Ctrl+Alt+Esc 紧急停止。

已实现的位置标记是独立的本地覆盖层：柔和目标光圈和短标签，默认 12 秒，可指定 3–30 秒，鼠标穿透、不截获点击。支持手部投影的 3D 角色在示意时短暂显示细弧线，起点跟随实际小手，随后淡出；图片角色只显示光圈和标签，不估算头部或身体连线。根据本轮最新截图的窗口、物理坐标与显示器映射到 Qt 坐标；目标窗口移动、尺寸改变、关闭或前台切换时撤掉标记，重新截图后才能再次定位。它不依赖 UIA 控件信息。

每次明确的指路请求先让同一只宠物看向目标。原位置安全且距目标不超过 160 个逻辑像素时留在原地；较远时从目标左、右、下、上选择可容纳整个宠物且不遮住目标的位置，用轻微弧线缓入缓出地靠近。停稳后，浮灵通过肩与肘弯曲轻轻示意一次，约两秒后放下小手，光圈和标签继续保留。没有空间时只显示标记；若原位置挡住目标，临时隐藏本体，撤销后恢复。到时或取消后回到指路前的位置；用户手动拖动立即接管，不再自动归位。自动移动的单独开关尚未实现。

下一次截图或实际操作前会撤掉指路标记。截图期间会临时排除本进程的可见窗口，结束后恢复；实际排除效果取决于 Windows 合成器与版本，仍待完整运行验收。实际点击继续使用新的 observation_id 和目标窗口校验，操作后重新观察。用户选择的目标失效时停下，不自动转去其他窗口。

### 指路接入与本地证据

`personal.computer` 增加 `guide` / `clear_guide`。`guide` 必须引用本轮有效截图的 observation_id，以 0–1000 坐标指定一个点或矩形，并可附短标签和时长；它不移动鼠标或点击。后端校验会话、共享授权及窗口身份，再通过 `pet.guide.request` 交给 Qt。只有前端实际到位才回复 `arrived`，无空间则回复 `indicator_only`；失效、取消和超时返回实际原因。

关闭共享、断线、停止或切换会话都会撤销指路。旧请求的迟到取消不会清掉新目标；本地每 200 毫秒复核目标窗口。目光和动画由本地驱动，不另开模型会话，也不增加周期观察。

早期候选阶段通过 `desktop/preview_guidance.py --render-only` 使用浮灵 B 与脚本自建窗口，记录远处靠近、近处原地示意、收手和归位，共 98 张连续画面。输出 [连续演示](../artifacts/pet-guidance/natural-v2/guide-natural.mp4)、[动作分镜](../artifacts/pet-guidance/natural-v2/storyboard.png)、[四方向实拍](../artifacts/pet-guidance/natural-v2/directions.png)和[帧状态记录](../artifacts/pet-guidance/natural-v2/observations.json)。该次只做渲染预览，没有运行自动测试；旧版 23 项检查记录不代表该次验收。预览仅使用本机 150% DPI 下的受限工作区和模拟目标，没有捕获其他桌面内容。浮灵现已正式接入；上述历史预览仍不能证明真实前台目标接受、模型工具到服务再到运行桌宠的整条链路及不同 DPI 已验收。

## 代码问题与精确跳转

例如用户问：“为什么 pageSize=0 最后变成 10？”助手读到工程中 `return pageSize || 10` 后，说明 `0` 被假值回退覆盖；如果 `0` 合法，应考虑 `??`。回复同时显示文件和行号，提供“打开第 42 行”。

代码入口来自用户指定工程、拖入文件、报错日志或明确的屏幕任务。仅凭截图得到的猜测要标成待核实；要判断完整原因与给出修改，优先读取相关源码和日志，不把屏幕上看见的一小段当成整个项目。

结果应使用结构化位置，例如 `source_location { path, line, column }`，由界面显示和业务层校验。路径不存在、行号非法、定位过期时给出原因。修改文件后更新行号，不继续使用旧位置。

前端新增一个受校验的“打开位置”桥接入口。先检测用户实际安装、选择的编辑器；VS Code / Cursor 等可以通过支持的参数跳到文件行，调用时传独立参数，不拼接 Shell 命令。其他编辑器按实际能力适配；只支持默认打开文件时明确说明无法精确跳行。

“指出问题”“跳到位置”“修改代码”是三个独立动作。前两个不默认编辑文件。用户明确要求修改时，再通过现有 Codex 执行链修改；验证遵守工程 AGENTS.md，不自行增加或运行测试。

代码位置卡不要求共享屏幕：已经有源码和日志时，文件定位可以直接完成。若用户想看编辑器里的具体位置，再按共享授权显示屏幕标记。

## 动画跟随真实状态

| 语义状态 | 动画方向 | 触发来源 |
| --- | --- | --- |
| 陪伴 | 呼吸、眨眼，低频动作 | 本地待机 |
| 在听 | 侧耳、轻微反馈 | 麦克风实际开始监听 |
| 在想 | 思考姿态 | 当前请求进行中、暂无工具动作 |
| 在看 | 看向目标窗口或拿放大镜 | 实际截图、阅读事件 |
| 在做 | 专注姿态 | 实际电脑操作或代码执行 |
| 等你 | 轻提示，停止工作动作 | 等待审批、问题回答或用户接手 |

结束时用一次短反馈回到陪伴；失败使用疑惑或提醒，不能继续播放成功动作。只显示一个主状态，优先级建议：等待决定 > 执行 > 观察 > 思考 > 陪伴；语音播放与监听按实际生命周期协调，避免同时表现“听”和“说”。

连续语音沿用一分钟无输入回到待唤醒的行为，生成与朗读不计入这段空闲时间。宠物动作不改变授权，不反向触发模型请求。

以上列的是工作语义状态，完整角色还需要散步、玩耍、互动和休息的动作库，以及完整的小行为片段。现在先定义状态接口，沿用已有素材；新角色从日常片段和协助片段一起验证，再逐步扩大动作。跟随目标的目光与手势可分层实现，不必为每个屏幕位置重画一套动画。

## 主动陪伴与周期思考

用户希望宠物能偶尔看看当前工作，真正调用模型判断能否提供帮助，并根据情境改变动作。这是一个单独的可选能力；普通对话和仅开启共享屏幕仍不启动模型心跳。

### 一个入口，两种节奏

宠物菜单增加“主动陪伴”开关，默认关闭，不跨启动、断线或会话切换保留。开启需要有效的共享授权；共享未开时显示需要先共享屏幕。入口说明“定期看当前工作窗口，偶尔给建议”。开启不等于立即执行电脑操作。

本地负责呼吸、眨眼、目光、姿态过渡和偶尔伸懒腰；不为每个动作调用模型。Codex 负责低频判断：当前场景是什么、采取哪种姿态、是否有具体值得提醒的事情。判断结果可以是保持安静，不必每次产生一句话。

初始建议每 3 分钟检查一次是否值得观察，每小时最多 20 次模型判断；这是调度上限，不是保证每个时点都调用。用户正在聊天、录音、等待审批或执行任务时跳过，错过的观察不补排队。锁屏、休眠、目标不可用时暂停；长时间无键鼠输入时转为低频陪伴，不凭空认定用户在做什么。

到时先用本地状态判断目标是否合适，再按授权捕获当前前台工作窗口；排除宠物与标记。仅在窗口或画面发生有意义变化时提交模型；重复画面跳过。不能通过持续调用大模型来检测变化，也不需要不断上传全屏。图像比较要允许忽略光标闪烁、小动画等噪声。

### 有情境的动作，有分寸的帮助

| 情境 | 本体表现 | 是否开口 |
| --- | --- | --- |
| 正在写代码或输入文字 | 安静坐着，偶尔看向编辑器，身体略微前倾 | 通常保持安静 |
| 阅读文档 | 跟随阅读方向调整目光，偶尔换姿势 | 确有需要时提示可以整理重点 |
| 看到清晰报错 | 轻微疑惑，靠近一点，显示一个小提示 | “这里有条报错，要我一起看看吗？”；截图判断标为待核实 |
| 当前任务确实成功 | 一次短促的开心反馈 | 按真实任务结果回复 |
| 长时间没有活动 | 打盹、整理衣角、伸懒腰等本地动作 | 不循环问“你还在吗” |

模型返回受校验的有限决策：保持安静、调整姿态或提出帮助，以及短提示、观察依据和可选目标。模型不能直接生成并执行动画代码、Shell 命令或任意动作名称。姿态可以带目光方向与强度，由本地平滑过渡，避免每次判断后突然切换整套动画。

轻提示不抢焦点、不自动展开聊天面板，默认不朗读；同类建议至少间隔 10 分钟，同一问题被忽略后不反复提醒。用户点提示后进入现有对话，带上那次发现的简短上下文；先重新核实目标，再进行阅读、定位或用户要求的操作。发现过期就撤掉提示。

本体负责陪伴和说话，也可在用户选择“指给我看”或持续协助时移动到目标软件附近，以目光、身体朝向和桌面标记引导；无需伸出一根手指。指路以准确标记为基础，窗口变化时撤掉过期标记。本体不遮挡内容与点击，任务结束后回到用户安排的位置。第一版不制作独立分身。

### 同一内核，真实的只读边界

周期观察复用当前桌面会话的 Codex 线程，增加内部的“陪伴观察”来源，与用户请求区分。同一线程只允许一轮写入；用户输入到来时，取消正在进行的观察，等原生轮次真正结束后再执行用户请求。空闲观察不另建模型会话，也不通过后台任务绕开桌面队列。

需要新增后端只读观察授权：这一轮只获得限定目标的截图和观察上下文，不能点击、输入、执行命令、读写文件、发送消息或创建任务。现有共享能力包含电脑操作，不能把它直接复用于自主观察，仅用提示词约束。实现时必须验证 Codex 原生工具权限与业务工具授权都能在观察轮次拒绝副作用；做不到时不启用此功能。

陪伴观察不能直接进入普通消息流水线：否则每 3 分钟出现“思考中”卡片，还会刷满聊天记录。它使用安静的结果通道，只把用户接受的建议转成可见对话；被跳过的观察不写成聊天消息。实际发生的原生模型轮次仍会占用 Token 和 Codex 线程上下文，不能宣称完全没有历史或成本。

短期陪伴状态只保存当前目标、上次建议和少量情境摘要；不把截图原文写入业务长期记忆。原生线程记录及其记忆行为仍需核实，不能承诺发给模型的画面不会被原生系统记录。设置可排除应用；初版优先允许用户选定的工作应用，敏感窗口不提交。

每小时调用上限之外还应有每日消耗上限，达到后回到本地陪伴；具体数值按实测消耗设置，不能把 Token 上限换算成未经核实的金额。关闭主动陪伴立即停调度、取消观察；关闭共享、紧急停止、断线和换会话也同时撤回观察授权。已提交给模型的图片不能通过关闭开关撤回。

主动陪伴第一版只做“低频观察 → 安静 / 姿态 / 一条帮助提示”，先验证是否自然、有用、不打扰。随后再完善角色动作、本体停靠与指路，以及用户明确授予的更具体主动任务，不直接加入自主点击或修改工程。

## 落地顺序

第一步统一面板：宠物入口与聊天窗口已落地；卡片、快捷输入仍独立，后续继续整合为一个输入区、一套消息内容，补旧记录查阅、阅读展开及一致的窗口生命周期。保留现有连续语音、文本选择和附件行为。

第二步让助手会指路：目标标记、本体移动及截图排除已接入，移动已完成本地预览；继续验证真实服务链路和截图排除效果，再加入文件行号定位和编辑器跳转。

第三步重新设计宠物动作：根据已经跑通的状态定义制作少量一致的动画，让动作、对话、指路和执行同步；加入本体移动停靠，不制作独立分身。新角色的头部或半身样机可以与前两步并行验证，先确认桌面尺寸下的表情和渲染质量，再扩大制作。

第四步加入可选的主动陪伴：先打通受限观察、同一线程调度与轻提示，再把情境决策接到新宠物动作上。可在新角色制作期间先验证观察与提示是否有帮助。

暂缓：常驻大侧栏、多模型切换、多宠物协作、连续画面流、复杂任务仪表盘。权限先把已有共享能力说清楚；周期观察的只读能力必须另行实现。

## 2026-10-26 聊天生命周期

聊天窗口发送消息后，发送按钮切换为“停止回复”；点击后显示“正在停止…”，直到后端返回终态才结束忙碌状态。前端用当前轮次标识关联请求，后端沿用当前会话的 `/stop`。停止与完成同时发生时，以实际收到的终态为准。

停止请求在本地发送失败或被服务端拒绝时，错误事件通过 `failed_event` 区分请求类型；窗口保留原回复，恢复停止按钮供重试，不将发送失败当作原任务已停止。

收起窗口不会取消任务。重新打开复用原窗口，保留草稿及接收中的回复。取消后保留后端返回的内容，并标明“已停止”；没有内容时只显示停止提示，不额外保存一条虚构回复。应用退出时，窗口释放自己持有的计时器和语音播放资源，连接仍由应用统一管理。

发送后的接收确认可以跨短暂断线等待，最多 20 秒；连接中断本身不立即判定输入失败。服务仅在输入处理入口成功返回后记录原请求标识，重连时随尚未确认保存的回复补回 `input.accepted`；入口返回前已经重连时，也向当前会话连接发送确认。等待超时仍明确提示接收结果不确定，不自动重发可能已执行的输入。确认信息复用现有回复恢复状态，不另建重试队列；服务重启后的确认恢复不在本次改动范围内。

输入处理被拒绝时，优先向原连接返回错误；原连接已断开且已订阅该会话时，将错误连同原请求编号发给当前会话连接，让等待中的输入获得实际失败原因。错误不另行缓存；错误发生时尚无连接的情况仍由上述确认超时提示处理。

静态验证：此前 6 个修改的 Python 文件语法解析通过，`event_client.py` 语法解析及连接关闭异常导入通过；本轮网关错误路由调整后，`npm run check`、`npm run build` 通过。当前未接入工程的桌面共享工具，尚未进行实际 Qt 窗口的发送、停止、收起、重新打开和断线恢复操作验收；停止请求失败重试、完成与停止竞态也仍需实机确认。

## 2026-10-27 回复状态解耦

将 `ReplyTurnMixin` 改为组合使用的 `ReplyCoordinator`：轮次查找、注销和断线恢复状态由独立对象管理；Qt 计时、窗口回调、宠物任务事件与历史写入由应用负责。移除没有调用的旧回复入口，流式文本统一保存在 `TextStreamState`，不再同步维护第二份文本。

代码复核覆盖停止请求、断线等待、恢复轮次、迟到回复与保存确认路径；保持先保存后确认投递，以及每轮只执行一次收尾的顺序。此次不增加重试层或后台任务。

## 交互验收要点

- 悬停入口不抢焦点，不开启共享；移开后收起。双击期间不误开入口。
- 双击宠物打开轻聊天，可在同一窗口展开完整记录，不追加单击触摸；单次右键只弹一次菜单，拖动不打开聊天。实体手势尚待运行验收。
- 默认与最小聊天尺寸下，长路径、Markdown 表格和消息不撑出页面；输入区与发送按钮可见。本轮实际 Qt 控件预览已通过。
- 日常问候、普通回复和结束语没有“已完成”，也没有固定复制 / 追问底栏。
- 用户选中文字、读长答案、输入草稿时，面板不自行消失；收起再展开保留内容。
- 开启共享不会发消息或截图；关闭后所有屏幕操作失去授权。
- 指路时鼠标位置不变；标记不挡点击；目标窗口移动后旧标记消失。
- 本体停靠避开目标；近处保留原位置，远处先注视再靠近，停稳示意后收手；用户拖动优先。归位已有本地预览，无空间降级本轮未复验，自动移动的单独开关待做。
- 电脑任务从执行到取消、失败或成功，都由真实事件驱动显示；收起不取消任务，停止可用。
- 代码跳转以真实文件与行号为依据；编辑器不支持时没有虚假成功反馈。
- 捕获图片中不出现宠物、回复面板与指路标记。
- 仅开启共享不启动周期观察；主动陪伴关闭时没有周期模型调用。
- 自主观察轮次在后端拒绝电脑操作、命令、文件修改和消息投递；不能只靠提示词声称只读。
- 用户输入优先，同一 Codex 线程不并发写入；观察取消完成后正常对话可继续。
- 周期判断不刷聊天记录、不抢焦点；重复画面、重复建议和调用上限都能抑制无效消耗。
- 关闭共享、断线、换会话或紧急停止后，旧观察与旧标记目标均失效，停止基于旧目标的自动移动。
