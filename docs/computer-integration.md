# 混合桌面能力实施方案

更新：2026-10-19。目标：让同一个 Codex 会话可靠地组合网页、文件和 Windows 桌面操作，并通过桌宠指示目标、展示结果和接受中断。

本文是本工程混合桌面能力的正式方案，统一记录当前设计、能力对比、实施顺序和验收结果；入口在工程 README。后续变更继续更新本文件与相关架构说明。

当前处于“核心功能已实现、整体验收尚未完成”的阶段。产品层面的完成标准、优先级和未来演进统一见 [产品路线与验收标准](roadmap.md)；本文继续维护桌面技术细节与实际验收证据。

## 当前方案与能力边界

Codex 负责理解任务和调用现有 personal 工具；gpt-claw 服务负责授权、目标复核、等待及取消。网页使用 Playwright，本地文件与命令使用现有原生工具；桌面由 Windows-MCP 控件采集、Win32 输入和桌宠截图/指示组成。

Windows-MCP 0.8.8 以依赖包接入内部只读适配进程，没有直接向模型开放其完整工具集合。适配复用上游采集器，输出限定窗口的结构化控件；元素操作仍通过现有鼠标键盘执行。尚未加入 UIA 原生 Invoke/Value、OmniParser、完整跨软件任务恢复或自动学习流程。

当前已实现：截图/语义/混合观察，当前观察内的元素引用及执行前身份复核，元素点击/输入/指示，文字和控件条件等待，语义失败时截图回退，授权撤销与取消重连，真实输入接管联动，以及服务内浏览器/桌面冲突协调。实现完成不等于完整实机验收通过，具体证据见本文交付记录。

## 与 Windows-MCP、dsh-orb 的对比

以下以本项目固定的 Windows-MCP 0.8.8 和本地 dsh-orb 提交 f540317 为比较基线，不作为上游未来版本的结论。

| 方面 | 独立 Windows-MCP | 本地 dsh-orb-cordis | 当前 gpt-claw |
|---|---|---|---|
| 定位 | 面向 MCP 客户端的 Windows 能力服务 | DSH 的悬浮球与 Computer Use 插件 | 飞书、桌宠共同连接的个人助理 |
| 桌面观察 | UIA 信息和可选截图 | 主流程按前台应用截图观察 | 指定窗口的结构化控件与截图组合 |
| 输入 | 坐标及部分元素标签定位的工具 | 根据截图坐标通过 SendInput 操作 | 当前观察的元素引用或坐标，元素操作前核对 RuntimeId、窗口及边界，仍用 Win32 输入 |
| 等待 | 原生 WaitFor 支持多种 UI 条件 | 固定 wait/long_wait 后重新截图 | 在同一授权窗口范围内等待文字、控件存在/可用/焦点 |
| 浏览器 | 提供浏览器相关观察、抓取和桌面操作 | 系统浏览器配合 GUI，另有网页搜索/抓取 | Playwright 的独立个人浏览器，按会话管理标签 |
| 交互 | 由接入客户端提供 | Electron 悬浮球、流式面板、观察边框 | Qt 桌宠、语音、卡片、目标指示和飞书 |
| 权限 | 工具选择、控制权策略；任务授权由宿主另行组织 | Access preset、进程内 GUI 锁，GUI 安装即授权 | 桌面工具绑定 UI 连接、共享租约和当前轮次，元素引用绑定当前观察 |
| 平台 | Windows | Windows、macOS | 本轮新增桌面能力限 Windows |

相比独立 Windows-MCP，本工程的增量是把桌面能力接入既有聊天、文件、网页、交付和宠物交互，并统一当前任务的目标与授权。截图加 UIA、条件等待和用户接管本来也是 Windows-MCP 的能力，不能宣称为本项目独有。

相比 dsh-orb，本轮明确增加的是主链路中的语义观察、稳定元素身份和条件等待。dsh-orb 已有前台 GUI 与后台 Code Agent 分工、成熟的悬浮球交互和跨平台积累；“支持后台代码任务”或“能跨软件操作”也不是本项目独有优势。

当前不宣称全面更快、更省或成功率更高：还没有覆盖常用任务的对照数据。Windows-MCP 完整工具面与接管策略更丰富；本地 dsh-orb 的观察边框、截图排除和交互实现已有积累。本工程的整体收益还需要完整桌宠和实际工作流验收。

## 架构决定

- 保留 Codex 为唯一模型执行内核，保留 `personal.computer`、`personal.browser` 和现有桌宠通道。
- Windows-MCP 作为服务内部的按需 stdio 子进程接入，使用项目已有的官方 MCP SDK；不向 Codex 再暴露一套独立 Windows 工具，不创建第二套模型循环。
- 现有 `ScreenShare` 继续控制桌面授权。必须先通过 UI 租约、聊天和当前轮次校验，才可以观察、等待或输入；关闭共享、取消及断线终止后续调用。
- 浏览器优先 Playwright；桌面组合 UIA 语义与截图，输入先复用现有 Win32。控件坐标点击与 UIA 原生 Invoke/Value 必须明确区分。
- 新增模块按实际职责划分，不预建插件总线、通用工作流引擎、模型路由器或多层 provider 抽象。实现一个使用点后再判断是否值得抽象。

## 第一阶段交付

1. 核实并固定 Windows-MCP 发布版的真实接口、依赖和返回结构，不能按 README 或模型猜测接口。当前 PyPI 为 0.8.8，要求 Python >=3.14；桌宠的 Python 环境保持独立。
2. 增加内部连接服务：按需启动、限定工具、显式超时、取消、错误说明和退出清理。子进程不继承业务凭证，日志不包含屏幕正文或连接凭证。
3. 增加语义/混合观察。所有返回的元素引用属于具体观察、窗口和轮次；限制数量与大小，明示覆盖不足和截断。只有验证了稳定结构及目标窗口范围，才能开放元素操作。
4. 增加有界条件等待。成功、超时、目标丢失分别返回；超时不自动重放前面的操作。等待不持续调用模型。
5. 复用现有 `guide` 和输入能力；指定坐标的 type 必须真正定位输入目标，不再默默忽略坐标。
6. 修复浏览器取消信号传递，取消后的排队动作不得继续执行。已发出的 Playwright 操作不能承诺回滚。
7. 文档说明安装、启用、故障排查、验证状态和回退路径。保持现有纯截图能力可用。

## 必须先核实的上游限制

Windows-MCP 的 Snapshot/WaitFor 是否支持限定 HWND、是否返回结构化元素及边界，必须查看固定版本的实现。如果只能返回全桌面文本，不通过解析易变的显示表格伪造稳定元素 ID，也不把模型提供的文字当成可执行控件引用。此时先交付可验证的观察/等待能力，明确范围，并记录下一步最小必要适配。

核实结果：0.8.8 的原生 Snapshot 返回展示文本，region 也不等价于只读取指定 HWND。`integrations/windows-mcp/observer.py` 直接复用上游 `Desktop.tree.get_state(hwnd, [])`，每次只进入宿主授权的窗口。Python 侧公开一个只读 `ObserveWindow` 工具；Node 侧使用 SDK 校验结构化结果。条件等待由宿主在同一授权内复用此观察，避免原生 WaitFor 再次扫描其他窗口。使用了固定版本的内部采集接口，升级时需核对，不可直接放宽版本号。

真实窗口验证发现上游普通桌面采集省略静态文字，且控件类型使用系统语言。适配在同一次上游遍历中补充 TextControl 和具名禁用控件，记录已有缓存中的 RuntimeId 与非本地化类型，不增加第二次完整树扫描。总遍历额外限制为 1024 个节点，输出最多 256 项，超限明确 truncated。

截图取自应用可见区域，不等于获得被遮挡窗口的实际内容。UIA 读取不等于可以在后台操作任何软件。禁止因观察失败自动扩大范围、启动提权或改用任意 Shell。

## 安装与使用

在 Windows 工程目录执行 `npm run computer:setup`。需要 PATH 中的 uv，使用独立 Python 3.14 环境和提交的 `uv.lock`；不使用桌宠的 Python 环境，也不安装全局 Windows-MCP。环境在 `integrations/windows-mcp/.venv/`，首次安装需要联网。服务启动不会自动捕获屏幕；首次授权的语义观察才启动只读子进程，退出或采集超时/取消会清理连接。

重启服务与桌宠。开启共享后发送新请求；首次电脑工具调用后，提示会变为“正在查看或操作电脑”，此时真实鼠标操作可接管。接管会关闭共享，继续任务需重新开启共享并发送“继续”。开启共享但尚未执行电脑工具时不会监视接管。语音或闲聊不会自行启动桌面观察。

电脑工具示例：

- “看看当前界面，找到保存按钮并指给我看”：observe 默认 hybrid，返回图片及本轮元素引用；guide 使用同一 observation_id 和 element_ref。
- “只读取当前窗口控件”：observe mode=semantic，不请求截图；后续鼠标动作仍校验窗口与遮挡。
- “等导出完成”：先观察，再 wait_for condition=text_exists、match_text=目标文字，timeout_seconds 最长 30 秒；匹配当前采集到的控件/静态文字，不是全屏 OCR。还支持 element_exists、element_enabled 和 focused_element，role 使用观察返回的 EditControl/ButtonControl 等类型。
- 纯截图仍使用 screenshot，不依赖语义环境；坐标以截图为依据。type 必须提供 element_ref 或 x/y，明确点击输入目标后再输入。

每次输入返回新截图并使旧元素引用失效；需要元素引用时重新 observe。元素引用是当前快照中的短期引用，不是永久 UIA ID；重采集核对 RuntimeId、窗口、名称、角色和矩形，但无法保证 UI 没有在检查后立即变化。通过元素引用输入时只接受已识别的编辑、文档或下拉输入控件。

`truncated=true` 表示达到上游节点/输出上限或采集不完整；控件可能缺失，不能据此断言不存在。hybrid 模式下语义读取失败会返回截图及 semantic_status=unavailable；semantic 模式明确报错，取消不会自动回退。自绘区域继续使用截图。密码控件不返回值，且不可通过元素引用操作。桌宠截图期间会临时设置本进程可见窗口的捕获排除属性，结束后恢复；实际排除效果取决于 Windows 合成器与版本，尚待实机验收。

故障排查：缺少依赖先运行安装命令；版本/结构不兼容时先检查固定版本适配，不解析展示文本；UIA 卡住时请求超时将关闭子进程，下次观察重新连接。等待 timed_out 或结果截图失败时，先重新观察实际状态，不自动重做提交。
