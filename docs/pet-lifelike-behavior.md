# 浮灵的日常生活与互动设计

目标是让 gpt-claw 专属宠物成为有注意力、有生活节奏、能回应本人的桌面助手。判断标准不是随机动作的数量，而是用户能读懂它此刻想做什么，以及自己做出反应后它会怎样回应。

## 第一阶段：已接入的本地行为

现有角色保留 16 个基础动画：待机、行走、坐下、玩耍、倾听、休息、思考、说话、招手、伸展、张望、整理、指引、等待确认、拖动和掉落。掉落默认关闭，日常悬浮不受重力影响；可在动作反馈菜单中开启。

当前在这些动画上编排了 **23 组连续活动**，加上程序化姿态共 27 个动作状态；散步由运行时控制双臂交替前后摆动，幅度随移动速度变化。连续活动的数量不等于新增骨骼动画的数量。

下面保留原有 13 组活动说明；新增 8 组及后续 24 项姿态设计见 [动作扩展设计](pet-action-expansion.md)。新增活动已接入代码，尚待连续播放验收。

| 活动 | 连续过程 | 空间和道具 |
| --- | --- | --- |
| 伸个懒腰 | 停一停 → 伸展 → 放松 | 原地 |
| 整理帽子和飘带 | 张望 → 整理 → 放松 | 原地 |
| 四处看看 | 左右看 → 思考 → 再确认 | 原地，目光缓慢巡视 |

| 趴在任务栏边看你 | 靠近 → 双手搭边 → 看你 20 秒 → 离开 → 回来 → 招手 | 当前屏幕底部常驻任务栏，短暂看向附近鼠标，随后自然收回 |

小球可在玩球期间连续点击，给当前运动追加力度，不重启动作或重置位置；宠物睁眼跟球，等球落稳后笑眼点头、看向你，再淡出小球。收尾期间再次点球可以接着玩。球的位置和速度由独立的本地运动模块推进；尚无桌面物体碰撞或接球。推球活动仍是球和宠物共同移动，不是独立的桌面物理物体。头部单击或鼠标来回轻抚可触发亲近回应，睡着时则慢慢醒来并伸懒腰。招手后会等约 4.5 秒；鼠标新靠近并停留 0.8 秒后笑眼点头，无人回应则整理放松，短暂经过或鼠标原地停放不会误触发。详见 [触摸、招呼与陪玩使用说明](pet-companion-interactions.md)。

### 心态、节奏与注意力

当前提供自在、好奇、想玩、困倦、想打招呼、专心协助六种心态。它们是本地行为状态，不是另一个模型的人格或会话。

- 精力初值 0.8；普通活动缓慢消耗，休息和睡觉恢复，玩耍结束额外消耗。精力低时更容易休息。
- 好奇心初值 0.5；随空闲时间缓慢增长，探索后回落。
- 社交需求初值 0.3；随空闲时间缓慢增长，招手或被摸后回落。
- 按当前需求给活动加权，同一活动有 150–900 秒冷却，最近三组活动不连续重选。当前数值随桌宠进程重置。
- 日常陪伴在启动或活动结束后等待 30–70 秒，活泼模式等待 16–36 秒。
- 鼠标靠近后短暂关注约 2.4 秒，累计移动至少 12 像素会续上关注；停住后收回，离开附近后最多保留 0.8 秒。空闲时每隔 5–9 秒小幅转眼，不持续盯着鼠标。
- 眼睛先看目标，头部稍后跟随，身体更慢地转向。视线服从实际占用状态：指引看目标，思考保持专注，睡觉维持闭眼；倾听和等待确认可暂时接管指引的视线。
- 安静陪伴只保留轻微待机和目光响应，不自动外出；“睡觉”模式持续闭眼、低头、收手并缓慢呼吸。两者都可手动选择活动，工作状态可以唤醒，结束后恢复。
- 拖动、任务状态、倾听、说话和指引优先于日常活动。任务进入时收起小球、停下外出并平滑转正；任务收尾后慢慢回到活动中心。返回也可被新任务打断，之后继续；主动摆放、切换模式或选择新活动会取消旧返回安排。
- 鼠标靠近时暂停外出位移；原地玩球、睡觉、摸头回应和任务栏搭边观察可以继续。按住鼠标或打开自身聊天/语音/输入面板、菜单时暂停自主活动进度和位移。基础动画的呼吸等细动仍可继续。

普通外出限制在用户最近一次摆放位置附近：水平 ±240 像素、垂直 ±100 像素，且夹在当前屏幕可用区内。散步一段约 90–170 像素，推球约 55 像素；采用缓入缓出的轨迹。拖动、缩放或明确移动会重设这个活动中心。

任务栏活动单独按屏幕可用区底边定位，双手接触点从当前 Qt 视口投影计算。边缘以下的画面与输入区域一起裁掉。当前支持底部常驻任务栏；自动活动只在宠物靠近底边时选择它，冷却 600 秒，手动选择不受距离限制。聊天任务、拖动、缩放或屏幕几何变化会取消并恢复完整可见位置。

入口：宠物菜单或托盘菜单 → **陪伴方式**。其中的 **一起玩** 可按类别主动选择这 23 组活动（21 组可自主选择，2 组仅点播），菜单顶部显示当前活动/心态。模型任务进行中不接受新的自主活动；没有可用底部任务栏时，搭边活动不可选。

## 最终体验：动作要有前因和后果

一组行为应包含五个部分：

1. **动机**：好奇、想亲近、困了、想玩，或正在协助本人。
2. **注意**：眼睛先看目标，头部跟随，身体最后转向；保留短暂停顿。
3. **行动**：移动、接近、藏身、推球等主体动作。
4. **反馈**：本人靠近、点击、呼唤、拖动或忽略，都有对应反应。
5. **收尾**：回到舒服的位置、整理飘带、休息；不是瞬间跳回待机。

例如“偷偷看我”：它先看一眼你正在用的软件边缘，慢慢飘过去，在窗口后停住，只露出半张脸。约一秒后稍微多探出一点；鼠标靠近时先停住并看向鼠标。你点它，它就走出来招手；你继续工作，它看一会儿便缩回去，之后回到常驻位置。这个过程需要真实窗口遮挡，当前第一阶段还没有实现。

日常活动占用注意力应少于协助和直接互动。一个舒服的陪伴周期应有大量安静观察，少量活动高潮，最后自然平复。活泼模式提高活动频率，但也保留停顿。

## 心态设计

长期性格保持稳定：亲近、好奇、有一点调皮，协助时认真。短期心态影响动作幅度、目光、停顿和活动选择，不直接改模型身份。

| 心态 | 动作和节奏 | 适合触发的行为 |
| --- | --- | --- |
| 自在 | 肩膀放松、缓慢呼吸、停顿较长 | 整理、坐下、看风景 |
| 好奇 | 先转眼后偏头，小步接近，停下确认 | 探头、看图标、巡视 |
| 想玩 | 节奏稍快，完成后看向本人等回应 | 玩球、邀请一起玩 |
| 困倦 | 眨眼变慢，动作幅度减小，选安静位置 | 揉眼、打盹、睡觉 |
| 亲近 | 保留目光等待，朝本人轻微靠近 | 招手、被摸后的回应 |
| 专注 | 减少无关动作，目光跟随任务目标 | 倾听、思考、指引 |
| 困惑 | 执行失败后短暂偏头、停顿；摊手仍待制作 | 已绑定任务失败，澄清回应待接入 |
| 开心/得意 | 完成后笑眼挥手，摸头后放松；得意姿态待制作 | 已绑定任务完成与摸头，更多积极回应待接入 |

基础表情继续采用角色现有动画的眼睛、嘴部与修形。任务回应只对目标通道轻量叠加点头、歪头和微笑，保留肩肘等动作修形；新增回应也沿用这个边界。

短期行为状态保留在界面进程。只有真正需要跨重启的偏好，如陪伴模式、活动范围和用户明确选择的性格倾向，才进入本地配置。完整对话仍由 Codex 管理，宠物不重复建立上下文。

## 窗口藏身和图标互动如何实现

### 软件后探头

当前宠物固定置顶。直接把身体裁掉会像图层被切断；仅改变窗口层级也容易整个消失。因此这项能力需要独立的环境与遮挡接入：

1. 由显式启用的环境互动能力提供可用窗口的边界、层级和生命周期，不把截图或窗口文字用于普通日常动作。
2. 选择宽度和遮挡条件合适、稳定的侧边；任务指引、拖动、菜单打开期间不选择目标。
3. 路径分为接近、进入遮挡、探出、等待、走出。宠物自身的可见轮廓和点击区域要随遮挡一致变化。
4. 对不规则窗口、圆角和窗口阴影核对实际遮挡效果；不支持的目标不进入藏身行为。
5. 目标移动时跟随几何变化；目标关闭/最小化时，平滑回到可见位置。不能遗留不可点击的隐藏宠物。
6. 鼠标靠近先停住；点击露出的脸时完整走出；开始聊天时立即回到清楚可见的协助位置。

实现时在真实层级遮挡与受窗口几何约束的合成遮挡间选一种可验证方案。先对普通矩形应用窗口完成接近、探头、退出闭环，再扩大支持范围；不能只用静态截图宣称完成。

当前工程的屏幕共享按请求开启，不能把旧共享状态当作日常感知授权。未来的持续窗口/图标互动需要单独、明确的开关与状态提示；当前活动只使用宠物位置、当前屏幕完整与可用区域、鼠标和自身面板状态，不读取其他应用内容或桌面图标。

### 桌面图标

先支持图标矩形和文字区的几何互动：绕行、观察、虚拟球反弹。点击宠物/球与操作系统图标的输入区域分开，留出点击和拖动图标的通道。文件移动、删除、打开等属于真实操作，走已有用户请求与工具权限流程，不能混进自主玩耍。

## 代码职责

- `desktop/src/pet/behaviors.py`：活动目录、步骤时长、心态分类、冷却。
- `desktop/src/pet/attention.py`：短暂关注、鼠标移动阈值、空闲转眼，以及招呼后的新靠近与停留判定，不依赖 Qt 或桌面接口。
- `desktop/src/pet/companion.py`：需求值、活动选择、步骤推进、优先级、位移与目光目标归属。
- `desktop/src/pet/ball.py`：独立处理球的追加力度、弹跳、滚动衰减和落稳，不依赖 Qt。
- `desktop/src/pet/companion_touch.py`：头部/球触摸、轻抚识别、单击等待和双击/拖动让位。
- `desktop/src/pet/surfaces.py`：任务栏可用性、接触位置、几何生命周期和窗口裁剪。
- `desktop/src/pet/spirit_view.py`：把姿态和展示参数传给 Qt，查询当前视口中的支撑点与触摸区域。
- `desktop/res/role/浮灵/CharacterSpirit.qml`：正式角色、朝向、倾斜、小球和接触点投影。
- `desktop/res/role/浮灵/assets/DreamSpiritRuntime.qml`：基础动画播放、手臂去扭转、程序化散步、睡觉与双臂支撑姿态、单手跟球、分层目光与飘带跟随。
- `desktop/src/pet/desktop_pet.py` 等现有窗口模块：拖动、面板、摆放中心和模式入口。
- 后续环境桥接只提供窗口/图标几何和明确事件，不把 Win32、Codex 协议或网络请求塞进活动目录。

本轮使用一个本地调度定时器，复用现有动画资产。没有新增模型轮询、第二套执行器、通用行为树框架或持久化需求数据库。

## 验收与推进顺序

1. **本轮**：先验证正式模型中球是否可见、六组代表活动的姿态和位置变化，完成 Python 静态检查与工程检查/构建。离散帧用于检查构图，不等同于完整动画和真人交互验收。
2. **P1 动作资产**：已有任务栏基础搭边姿态；继续补探头、窗口趴沿适配、揉眼、贴近、接球、收手等接触/过渡姿态。正侧面和中间帧检查肩肘细褶、穿模、手与道具间距。
3. **P1 环境互动**：先做一个普通窗口侧边探头闭环，检查窗口移动、关闭、切前后台、不同缩放比例下的退出和点击；再做图标绕行与阅读区域让位。
4. **P1 玩具互动**：已接入连续点球、目光与单手跟随、落稳后回应；继续补球与手的真实接触、追逐和收回，再验收邀请—等待—收到回应/未回应两条分支。
5. **P2 丰富性**：加入绕窗、球碰撞、偶尔失败再恢复、更多心态。用实际长期使用观察重复率和打断频率，调整节奏。

最终验收要包含连续活动而非单帧：同一行为从动机到收尾可读，动作衔接自然；指引和聊天随时能接管；窗口和图标互动有真实几何依据；安静模式可以长期放着；用户能主动邀请、回应和结束互动。
