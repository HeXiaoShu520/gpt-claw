## 从参考工程吸收什么

- `desktop/src/pet/behaviors.py`：把日常小动作与点播演出分开。演出数量不能当作骨骼动画数量，其他角色专用姿态也不能直接移植到浮灵。
- 活动选择器：保留心态权重、冷却和近期去重，让动作有停顿，不连续抽取同一活动。
- 分组菜单：动作数量增加后按用户意图组织，避免一长列名字。
- 时间问候、情绪小剧场可作为后续内容，但需要明确触发条件。工作成功、失败和等待确认必须来自真实业务状态，不能随机表演。

活动调度仅增加一个 `ambient` 属性区分自主活动与点播活动，沿用原有步骤执行器、任务接管和返回逻辑，不另建调度系统或模型会话。

## 制作与验收顺序

1. 先制作歪头、点头、迎接、扶帽、揉眼五项，解决最常见的表情与身体回应。每项检查正面、侧面和抬手中间过程，尤其肩根、肘部、帽沿与脸面穿插。
2. 再制作抱飘带和接球。先建立接触点与释放规则，手和道具不能各播各的动画。
3. 最后做窗口探头与图标互动。先确定环境几何和退出路径，再制作演出。
4. 所有活动都验证任务接管、拖动、打开聊天、切换安静模式与屏幕边界变化。动作不能阻碍用户输入；音效稀疏且可关闭，不默认给每步加气泡。

本轮完成 Python 语法解析，并使用生产入口 `CharacterSpirit.qml` 实际渲染三种新姿态：正面、侧面各取 0、0.7、1.65、2.7、4 秒，共 30 帧。固定睁眼，关闭自然扰动与切换过渡以单独检查姿态；采样中可见歪头、点头、张手及收势，没有看到明显肘部挤折。这不能代替连续播放或所有角度的网格验收。
