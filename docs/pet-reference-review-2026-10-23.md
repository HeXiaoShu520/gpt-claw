# 桌宠参考源码与浮灵动作设计

日期：2026-10-23。对象：gpt-claw 专属宠物。本文保留48项行为设计和源码研究依据；第一批12项已接入正式Qt路径，实际完成程度、复拍和剩余验收见 [实施记录](pet-behavior-implementation-2026-10-23.md)。其余36项仍为设计。

## 结论

上次只总结状态机，确实漏掉了最重要的内容：对方不只是动作多，而是有大量完整的小情节。偷吃会被发现，打瞌睡会被惊醒，工作被打扰会有反应，然后回去继续工作；道具也给动作提供了明确目的。

浮灵已有散步、睡觉、玩球、任务栏互动、拖动和落地反馈等基础，接下来应该补充有辨识度的表演、输入反馈和收尾，而不是继续把 `look / wave / stretch` 重新排列后算作新动作。优先补触摸回应、睡眠三段、任务栏撑手、任务中断后恢复，以及浮灵自己的月亮、飘带和星球道具。

### 研究开始时的浮灵基线

`desktop/src/pet/behaviors.py` 有 **13 条自主行为序列**：伸懒腰、整理、张望、托腮、招呼、任务栏活动、附近散步、巡视、颠球、追滚球、坐下、小睡、长睡；另有成功、失败、取消 3 条任务反馈。

运行时 **21 个状态**，底层使用 **16 段基础 Blender 动画加程序姿态叠加**。这些与“106 个视频文件”计数单位不同。不过，内容上的差距是真实的：现有很多序列仍在复用相同的看、挥手、伸展和玩耍姿势；动作的目的、手部接触和不同结尾还不足。

后续第一批实施增加困倦、醒来两个状态，当前为23个状态、16段基础动画和13条自主序列；不能把12项改进统计成12段新增动画。详见 [实施记录](pet-behavior-implementation-2026-10-23.md)。

已存在的气泡拖尾、轻音效、速度关联摆臂、惯性、落地眩晕和任务栏流程，见 [动作反馈实施记录](pet-feedback-2026-10-23.md)。该记录中的隐藏 Qt 帧和音频加载检查不等于完整桌面互动验收。

## 3. 每个项目具体学什么

### 3.1 主仓库：把演出做完整，而不是只做姿态

值得吸收的不是火锅、女仆或鲸鱼形象本身，而是这些情节结构：

| 源动作 | 使它成立的内容 | 浮灵可以采用的设计 |
| --- | --- | --- |
| 偷吃零食被抓住 | 专注偷吃 → 注意到你 → 停顿 / 装无事 | 偷啃光点 → 对视 → 把光点藏到身后 |
| 打瞌睡被惊醒 | 眼皮下降 → 点头失衡 → 惊醒 → 恢复 | 漂浮变低 → 月亮轻晃 → 扶帽醒来 |
| 吃冰淇淋融化 | 道具随时间变化，引出表情和补救 | 星星冰棒滴光 → 慌忙接住 → 松口气 |
| 玩游戏气急败坏 | 目标受挫 → 明显反应 → 回到活动 | 接星球漏接 → 鼓脸 → 再试一次 |
| 三球抛接 | 目光、手、球的时序关系 | 先单球练习，再双星轮换；漏接也有结尾 |
| 放风筝 / 吹气球 | 手与道具相连，身体被道具牵动 | 星形气球牵起身体，再轻轻拉回来 |
| 尾巴拍地 | 接触点、拍击节奏和回弹明确 | 浮灵尾尖轻点边沿，配合身体反作用 |
| 拆礼物 / 魔术 | 铺垫 → 揭晓 → 面向用户展示 | 双手合拢藏星 → 掀开 → 星星冒出来 |

动作选择还做了分组权重、不连续重复、事件槽轮换、文字素材禁止镜像。我们的安静陪伴应比该配置更克制，不直接照搬其空闲动作高权重。

移动素材有准备和收尾时间，角色不是整段匀速滑动。投掷物理记录近期指针轨迹，停住一会儿再松手不会沿用旧高速；碰撞后有速度关联压缩。这些细节比增加一个“摔倒”状态更影响手感。

视频端使用 A/B 两个元素，下一段加载后再换前景，并停掉旧元素及其结束回调。对 3D 的启发是明确动作交接与完成归属；不需要把 Qt 动画改为视频双缓冲。

来源：[选择器](https://github.com/PC2005-cloud/dsh-pet/blob/c696095c5786e0eeb25fec0f37a9cdcf30059151/dsh-pet/src/shared/pickers.ts)、[物理](https://github.com/PC2005-cloud/dsh-pet/blob/c696095c5786e0eeb25fec0f37a9cdcf30059151/dsh-pet/src/shared/physics.ts)、[视频切换](https://github.com/PC2005-cloud/dsh-pet/blob/c696095c5786e0eeb25fec0f37a9cdcf30059151/dsh-pet/src/client/pet.ts)。

### 3.2 Coopanion：摸、提、放，都有即时回应

- 连续抚摸按指针移动积累判定，不仅凭进入角色区域；有冷却。睡着被摸可以冒爱心，醒着有喜欢或害羞反馈。
- 拖动越过小距离才进入提起；真正飞行时可以立即接住。松手速度来自近期轨迹。
- 小幅放下与大力甩出表现不同；较大撞击进入眩晕，普通接触只做落地。
- 坐下时就决定是否进入睡眠，先困倦再睡；点击睡觉或坐着的角色会走醒来过程。
- 声音在步点、抓起、落地、抚摸等事件出现，而不是给整个循环不停铺音轨；静音和可见性统一控制。

浮灵最该补的是抚摸和轻点的差异、睡着时触摸的差异，以及由耳目可见的接触点触发反馈。不要把“鼠标碰到就挥手”当作抚摸。

来源：[身体交互](https://github.com/Pal-AI-Lab/Coopanion/blob/04ce022a8c1e96e6053d9cbbe8f6dc555aa93f33/packages/cortico-world-desktop-pet/web/kit/body.js)。

### 3.3 鲸鱼女孩分支：有上下文的中断和恢复

它列出 24 项普通随机演出、3 项点击回应、2 项移动；这些池之外还专门组织了以下行为：

- 睡觉：进入、循环、叫醒三段；空闲达到门槛才触发。
- 工作：开始 → 工作池循环 → 结束；被摸时播放打扰反应，然后返回工作池。
- 时段：早晨睡眼惺忪、中午吃饭、深夜犯困，有冷却。
- 任务结果：完成和失败都有多个表现，睡着遇到工作先醒来。
- 贴边探头：有独立图片和向内拖出流程。

最后一点需要特别区分：这个版本的探头是**屏幕边缘图片切换**，不是识别任意软件窗口后藏到软件后面。不能据此宣称我们的真实窗口遮挡互动已经解决。

浮灵可以学习“先醒来再倾听”“忙时抬头回应后继续”，但不照搬责怪用户的台词，也不把工作摸鱼演出当成真实执行状态。

来源：[动作池、睡眠、工作和贴边逻辑](https://github.com/yanzwzz/dsh-whale-girl-pet/blob/b5ce53cfa87b9fc669eef2aabe64946bb77adb72/lib/client.js)。

### 3.4 多角色分支：由需求和触摸位置改变选择

清单定义了角色序列、身体分区、空闲导演、精力、心情和亲密度。实际检查的 `jyn-loli/pet.json` 有头 / 身体 / 腿部触摸分区，以及挠头、鲸鱼抱枕、棒棒糖、摇摆舞四项空闲演出；睡觉能恢复精力。数值按经过时间结算，不需要额外模型心跳。

对浮灵适合保留的是少量本地状态：精力影响睡眠倾向，好奇影响探索，社交倾向影响招呼。不要引入需要每日打卡、付费养成或让用户负罪的饥饿机制。该分支有游戏化的随机工作成功 / 失败和奖励，不能映射为真实 Codex 任务结果。

同一个清单里的帧数也不能当动作数。例如鲸鱼 spritesheet 的 57 帧分布在多个序列中，并不是 57 项独立演出。

来源：[行为结算](https://github.com/zhu1090093659/dsh-pet/blob/fc1aa6b655d0e402a0de48af161edfcb4fbaf105/src/gameplay.ts)、[角色清单](https://github.com/zhu1090093659/dsh-pet/blob/fc1aa6b655d0e402a0de48af161edfcb4fbaf105/assets/jyn-loli/pet.json)、[序列播放](https://github.com/zhu1090093659/dsh-pet/blob/fc1aa6b655d0e402a0de48af161edfcb4fbaf105/src/client/sequences.ts)。

### 3.5 Python 移植：动作控制和位置控制分开

`sprite_behavior.py` 管素材状态，`sprite_physics.py` 管被甩出后的坐标；飞行时不会由两个循环重复推进位置。碰撞使用身体区域而非整张透明画布，飞行采用小步积分。落地前预热待机帧，落地后恢复播放速度，避免黑闪或让后续动作继承错误速度。

浮灵适合学习单一位置所有者、身体接触边界和播放速度复位。它的多屏处理也有实现，但本次没有运行多屏验收，不能当成可直接替换的成熟答案。

来源：[行为](https://github.com/MerZlin/dsh-pet-indesktop/blob/34d810b1eadd98d00e7cb9b3b51428a45b5bf03e/pet/sprite_behavior.py)、[物理](https://github.com/MerZlin/dsh-pet-indesktop/blob/34d810b1eadd98d00e7cb9b3b51428a45b5bf03e/pet/sprite_physics.py)。

### 3.6 Rust 独立版：参考宿主，不重复计算动作

源码是 Win32 窗口和视频解码路线，保存位置、朝向、缩放、置顶和禁止移动等选项；它复用动画素材，不能再把相同动作算成一份新增动作库。对已经采用 Qt 的工程，重写宿主收益不如完善现有动作和接触质量。

来源：[源码目录](https://github.com/ianlike-ui/dsh-pet-standalone/tree/6369388f05acc2fef61abdbd9851d1fec44778c3/src)。

## 4. 为浮灵设计的 48 项行为

下面是**设计清单，不是已完成数量**。其中已有行为也需要补齐接触、过渡或不同结尾，不能只改名字。P0 先打磨、P1 扩展、P2 后续内容。每项都要能被打断并自然回到当前活动。

### A. 日常小习惯

| 编号 | 触发与可见过程 | 反馈与收尾 | 优先级 |
| --- | --- | --- | --- |
| A1 | 长时间安静 → 看你一眼 → 微笑 → 视线回去 | 低幅度，不弹气泡、不打断工作 | P0 |
| A2 | 月亮轻晃 → 仰头 → 小手扶正月亮 | 月亮停止晃动，手回到身体两侧 | P1 |
| A3 | 飘带搭到身前 → 低头拨开 → 拍拍衣帽 | 手与飘带有接触；末端延迟回摆 | P1 |
| A4 | 原地坐久 → 先缩肩 → 双臂伸展 → 舒展呼气 | 不直接从待机跳到最大伸展 | P0 |
| A5 | 无聊 → 尾尖按节拍点边沿 → 意识到你在看后停一下 | 仅在有接触面时播放轻敲 | P1 |
| A6 | 好奇 → 抬头追一个光点 → 身体随后轻转 | 眼、头、身体分先后，回正柔和 | P1 |
| A7 | 休息 → 双手抱一枚小星 → 轻轻揉亮 | 光随揉动增强，最后送回胸前晶体 | P2 |
| A8 | 久未活动 → 左右伸展 → 整理飘带 → 看向下一目的地 | 接入散步准备，不再硬切移动 | P1 |

### B. 直接和用户玩

| 编号 | 触发与可见过程 | 反馈与收尾 | 优先级 |
| --- | --- | --- | --- |
| B1 | 轻点额头 → 先缩一下 → 看你 → 微笑或眨眼 | 两三种小反应，避免连续重复 | P0 |
| B2 | 连续轻抚头顶 → 眼睛眯起 → 顺手势轻靠 | 稀疏爱心、轻音可关闭，停止后缓慢恢复 | P0 |
| B3 | 点身体侧边 → 躲痒 → 小幅扭身 → 用手护住 | 独立于头部点击，不放大成疯狂扭动 | P1 |
| B4 | 鼠标在附近缓慢移动 → 看向指针 → 歪头 | 只用本地指针，不解释成读取屏幕内容 | P1 |
| B5 | 伸手示意 → 等待指针靠近 → 轻碰掌心 | 命中后亮一颗星，等待超时自然收手 | P1 |
| B6 | 玩耍模式 → 面向用户展开双臂 → 等回应 | 点中后抱一枚心形光点；不阻挡输入 | P2 |
| B7 | 用户选择捉迷藏 → 躲到屏幕边缘 → 露半张脸 | 点脸或向内拖出；明确只是屏幕边缘玩法 | P1 |
| B8 | 连续轻戳 → 小手挡一下 → 鼓脸 → 很快消气 | 不训斥、不扣亲密度，不妨碍双击聊天 | P1 |

### C. 移动与桌面接触

| 编号 | 触发与可见过程 | 反馈与收尾 | 优先级 |

## 5. 第一批落实的 12 件事

顺序按照“先把身体和输入做可信，再增加表演”排列。下表保留原始验收目标；代码接入不等于全部目标通过。撑手形变、手球精确接触及真实桌面验收仍有缺口，逐项结果见 [实施记录](pet-behavior-implementation-2026-10-23.md)。

| 顺序 | 交付项 | 核心验收 |
| ---: | --- | --- |
| 1 | C1 散步准备、摆臂与刹停 | 正面、侧面和转弯中间帧；速度变化时手不甩穿身体 |
| 2 | C2 任务栏撑手 | 接触前、承重中、离开后三阶段；肘不塌、手不滑、肩根不皱成团 |
| 3 | B1 轻点反馈 | 轻点、双击、拖动互不误触；连续点击不过度重复 |
| 4 | B2 抚摸反馈 | 持续移动才算抚摸；停手缓慢恢复；静止悬停不重复刷爱心 |
| 5 | D1 困倦点头 | 能读出“快睡着”，不会看成眼睛被脸遮住或眼球缩小 |
| 6 | D2 入睡 | 身体、手、眼和飘带自然收拢；没有瞬间换姿态 |
| 7 | D5 温柔叫醒 | 睡姿到睁眼到伸展连贯；手与帽沿不穿插 |
| 8 | D6 任务唤醒 | 用户可以立即输入；醒来后进入真实倾听 / 工作状态 |
| 9 | E1 手球同步 | 抛、落、接三个时点有明确接触，球不穿手 |
| 10 | F5 忙时被摸后继续 | 可见回应后回到当前任务；不丢状态、不重播过期庆祝 |
| 11 | F2 / F6 思考变体与结束区分 | 小动作有变化；多轮任务只有真正结束才庆祝 |
| 12 | E4 可戳泡泡 | 用户戳破与自动破裂的反馈不同；道具结束后回收干净 |

每件先做低幅度动画和连贯过渡，再增加音效、粒子；不能只用截图确认最终姿势。小手保持圆润、不放大，不额外做手腕；肘部要有上臂、前臂的方向关系，肩根平滑，不用持续夸张扭转驱动表现力。

默认悬浮、不自动掉落仍然保留。大力释放后的坠落演出只在用户启用掉落后出现。声音遵守现有静音、休息和语音规则，不能为了热闹重新铺持续音轨。

## 6. 工程怎样吸收，保持精简和解耦

沿用现有结构，先不新增一套宠物引擎或另一条模型会话。

| 现有位置 | 应承担的变化 |
| --- | --- |
| `desktop/src/pet/behaviors.py` | 声明有进入 / 停留 / 离开的序列、变体、冷却和允许的中断点；不直接操作窗口 |
| `desktop/src/pet/companion.py` | 选择活动，处理真实任务优先级，记住被打断前的休息意图；避免连续重复 |
| `desktop/src/pet/companion_touch.py` | 识别头部轻点、来回抚摸和道具点击；双击、拖动时取消待处理轻点 |
| `desktop/src/pet/desktop_interactions.py` | 分发输入与拖动、释放；同一时刻只有一个位置控制来源 |
| `desktop/src/pet/surfaces.py` | 提供接触面与可用区域；任务栏、未来窗口边缘都由这里给出几何信息 |
| `desktop/src/pet/feedback.py` | 接收抓起、接触、抚摸等明确事件，播放短音效或本地短句；不调用模型 |
| `desktop/res/role/浮灵/CharacterSpirit.qml` 与运行时资源 | 混合身体、表情、视线和道具；接触约束、过渡和实际形变在渲染层处理 |

新增设计数据只补当前结构表达不了的概念，不为每项动作创建一个控制器。动作完成、被打断和取消应能区分；已经被替换的旧回调不能把新动作切回去。

任务驱动只消费工程已有的真实事件。主仓库值得学的一点是把“中间结果”和“最终成功”分开，并让等待确认优先于空闲演出；具体槽位不需要照搬。来源：[工作状态联动](https://github.com/PC2005-cloud/dsh-pet/blob/c696095c5786e0eeb25fec0f37a9cdcf30059151/dsh-pet/src/host/work-status.ts)。

AI 可以按工程提供的语义能力请求“看向 / 指引 / 安抚 / 庆祝”，本地决定姿势、幅度和优先级。不要把骨骼角度、音效路径和随机动作列表塞进每轮提示，也不需要靠模型每秒决定一次动作。
