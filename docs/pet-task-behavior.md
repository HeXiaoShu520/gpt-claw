# 任务如何驱动桌宠

2026-10-21：将 gpt-claw 的对话轮次和任务结果接到正式浮灵角色。Codex 仍是唯一执行内核；桌宠在本地编排动作、表情和语音，不创建额外模型会话或模型心跳。

## 已实现的回应

| 工程事件 | 桌宠回应 |
| --- | --- |
| 开始一轮请求 | 轻轻点头约 0.9 秒，然后保持思考 |
| 收到执行进度 | 继续当前思考，不反复重播收到任务的动作 |
| 等待操作确认 | 切换等待确认姿态，后续进度不会把它覆盖；确认结束后恢复工作 |
| 成功完成 | 微笑、看看你并挥手，再回到待机；约 4.1 秒 |
| 执行失败 | 歪头露出困惑表情，张望后安静等待；约 3.2 秒 |
| 取消执行 | 收住动作、轻轻低头，再回到待机；约 1.4 秒 |
| 回复准备语音 | 合成期间保持思考，实际播放时切换说话，结束后释放语音状态 |

这是现有动画与局部姿态的组合，基础动作仍为 18 个状态、日常连续活动仍为 13 组。任务收尾可以在聊天面板打开时完成；散步、玩球等自主活动仍遵守面板和鼠标交互暂停规则。

## 调度与打断

多种事件同时发生时，按下面的优先级决定姿态。等待确认、倾听或指引结束后，仍在执行的任务自动恢复思考。

视线同样服从当前占用来源：只有指引实际占用时才看向指引目标；倾听或等待确认接管后，会看向附近鼠标，否则面向前方。释放占用后再恢复指引目标。分层转向与回放结果见 [注意力与视线验收记录](pet-attention.md)。

| 来源 | 优先级 |
| --- | ---: |
| 拖动 | 100 |
| 下落状态 | 90 |
| 等待确认 | 70 |
| 倾听 | 60 |
| 指引、指引移动及返回原位 | 55 |
| 语音播放 | 50 |
| 任务执行、语音准备 | 40 |
| 日常活动、触摸回应、任务收尾 | 无工作占用时播放 |

成功、失败或取消时，如果仍有语音、指引或其他任务占用，会暂存最近一次收尾。占用在 **6 秒内**结束才播放，超过期限就跳过，避免隔很久突然庆祝。新任务会丢弃上一轮尚未播放的收尾；拖动会中断并清除收尾。多个任务并行时，结束其中一轮不会清除其他轮次的工作状态。重复终态消息不会重复回调或重复播放。

指引返回原位期间仍持有指引优先级，避免边返回边被思考或自主活动抢走姿态。取消、失败和正常完成通过 `task_outcome` 区分；该字段随原有投递队列保存和重试，不新增存储层。

散步或其他外出活动中接到任务，会停下位移，沿当前朝向平滑转正；任务收尾结束后，先看看周围，再缓慢回到最近一次摆放的活动中心。返回途中接到新任务会再次停下，忙完继续返回。聊天面板、输入、菜单等交互和鼠标靠近仍会暂停自主返回；任务收尾本身可以继续播放。

拖动重新摆放、明确移动、切换陪伴模式或主动选择另一项活动会取消原来的返回安排，避免宠物回到用户已经放弃的位置。状态文字和姿态共用同一套优先级，能区分思考、倾听、等待确认、指引和睡觉；指引返回阶段即使使用待机姿态，也显示“指引中”。

## 实现边界

- `src/app/ports.ts`、`outbox.ts`：在已有回复目标中传递完成、失败、取消结果。
- `src/desktop/gateway.ts`：随终态 surface 消息发出 `task_outcome`。
- `desktop/src/reply_coordinator.py`：用明确的轮次 ID 驱动开始和结束，避免多个请求共用一个思考开关。
- `desktop/src/app.py`：接入等待确认、实际语音播放和任务结果，清理结束后的状态占用。
- `desktop/src/pet/companion.py`、`behaviors.py`：调度优先级、短回应和延迟收尾。
- `desktop/src/pet/guidance.py`：指引移动与返回期间保持占用。
- `desktop/res/role/浮灵/CharacterSpirit.qml`、`assets/DreamSpiritRuntime.qml`：传入回应进度，在现有骨骼与表情通道上叠加点头、歪头、微笑。

没有要求模型逐帧发动作。普通任务生命周期由工程自动表达，模型仍通过现有工具按需发起指引和互动。此次没有增加其他窗口或桌面图标的感知能力。

## Qt 验证

使用正式 `SpiritView`、角色 QML、`CompanionDirector` 和轮次协调器，在隔离窗口连续推进并保存 **636 帧 Qt 帧缓冲**，回放 30 次事件，覆盖收到任务、重复进度、确认与恢复、成功、失败、取消、语音占用后的收尾、指引与倾听优先级、拖动中断、新任务替换旧收尾和两个并行请求。

9 个轮次的结果回调各触发一次，回放结束时活跃轮次为 0，QML 错误为 0。已检查画面对照，收到任务的点头、完成后的挥手与笑眼、失败时的歪头及取消后的收势能够呈现。

另用同一正式角色与协调器回放外出中断和返回过程，保存 **924 帧 Qt 帧缓冲**，推进 25 次事件。5 个任务结果各回调一次，结束时活跃轮次为 0，QML 错误为 0。回放确认：

- 接到任务的事件不再瞬间清零朝向，后续帧平滑转正。
- 聊天面板打开时完成回应可以播放，但返回位移暂停；关闭面板后回到活动中心。
- 返回中接到第二个任务可以再次中断，取消收尾后继续返回。
- 拖动放下后以新位置为活动中心，不再返回旧位置；切换安静模式会取消待返回安排。
- 等待确认、倾听、指引、思考和睡觉的状态文字与当前占用来源一致。

已检查前后帧对照中的朝向、回应表情和收势。以上为隔离渲染与事件回放，不能替代真实鼠标交互和长期使用观察。
