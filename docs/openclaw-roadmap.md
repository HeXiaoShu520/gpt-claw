# 相对 OpenClaw 的缺项与演进规划

核对日期：2026-09-28。范围是本人电脑上的个人助理。这里比较软件提供的能力；插件、额外模型服务、设备授权和实验功能不等于安装后全部可用。优先级与难度是本工程的设计判断，不是 OpenClaw 官方评级。

2026-10-18 说明：本文保留 2026-09-28 的历史对照与当时判断，不作为当前能力清单，也不表示上游现状已经重新核实。项目当前优先级统一见 [产品路线与验收标准](roadmap.md)。Windows 桌面截图、点击/输入、控件观察、条件等待与接管联动后来已有实现，完整实机验收仍未完成，具体以 [混合桌面实施方案](computer-integration.md) 为准；下表“还不能点击或键入”等描述仅代表当时状态。

## 1. 当前处于什么位置

gpt-claw 是 Codex 的飞书客户端与个人业务服务层。它复用原生执行、Skills 和 MCP；已有浏览器、记忆、后台及定时任务的基础实现。OpenClaw 还提供通道、运维、记忆、工作流、设备和多种运行时的整套助理平台。两者都能聊天和调用工具，但平台覆盖面和运行可靠性并不相等。

OpenClaw 当前也有 Codex harness / app-server 接法，并非只能运行它自己的默认内核。因此不能用“支持 GPT 会员”“能执行命令”“有 Skills/MCP”作为独有优势。[官方 Codex harness 文档](https://docs.openclaw.ai/plugins/codex-computer-use)

## 2. 能力对照

| 能力 | gpt-claw 当前 | OpenClaw 提供的对应范围 | 本工程处理方向 |
|---|---|---|---|
| 聊天/人物/引用/卡片 | 飞书专项解析与原文读取；本人专用 | 多通道、群提及、配对、路由 | 先打通真实飞书链路，维持单人 |
| 原生 Agent 执行 | Codex 线程、命令、文件、搜索、压缩、审批 | Agent 与不同 harness 接入 | 继续复用 Codex，不重写循环 |
| 浏览器 | 独立 Edge、快照/输入/截图/标签 | 多配置、现有会话接入、下载、PDF、远程浏览器 | 优先补下载、上传和稳定定位 |
| 桌面应用 | 桌宠展示、输入、确认、图片和本人点击后的窗口截图；还不能点击或键入其他应用 | Codex Computer Use / 外部桌面驱动接入，受平台条件限制 | Windows 桌面执行适配单独立项 |
| 长期记忆 | Codex 原生本地记忆与线程续聊 | 混合检索及可选记忆插件/知识层 | 优先补原生记忆的可见性和纠错入口 |
| 后台工作 | 简单状态与并发；不自动重放 running | 活动记录、子任务关联、通知与运维入口 | 补进度、交付恢复、受控续跑 |
| 定时/事件 | at/every/cron；显式创建后才运行 | 多种自动化 payload、事件触发、投递策略 | 加文件/邮件等事件入口，默认关闭 |
| 多步骤工作流 | 模型自行编排；没有持久化步骤检查点 | 可选 Lobster 确认与恢复、Task Flow | 高频重复流程先确定性编排 |
| 故障切换 | 单个 Codex 进程；故障明确失败 | 认证轮换、模型 fallback、暂时故障恢复 | 先做同运行时恢复，不自动换计费方式 |
| 操作界面 | 飞书、终端、专属桌宠与聊天窗口 | Control UI、原生/移动端相关界面 | 补任务和连接状态视图 |
| 媒体 | 飞书图片/附件；桌宠图片展示和可选本地 ASR/TTS | STT/TTS、更多音视频与生成能力 | 保持语音按需使用 |
| 插件维护 | 本地 TS、原生 Skill/MCP | 插件体系、安装/管理与平台运行时接口 | 明确稳定 Tool 契约与版本兼容 |
| 运维/保留 | 实例锁、收发件持久化、简单 doctor | 平台配置、诊断、状态和维护入口 | 自启、备份、迁移、保留策略 |

多通道、媒体、设备与运行时覆盖见 [Features](https://docs.openclaw.ai/concepts/features)。浏览器具体差距见 [Browser](https://docs.openclaw.ai/tools/browser)；背景状态不是工作流恢复，二者在 OpenClaw 也分为 [Background tasks](https://docs.openclaw.ai/automation/tasks) 与 [Lobster](https://docs.openclaw.ai/tools/lobster)。

## 3. 按重要性与难度排序

| 阶段 | 项目 | 收益 | 难度 | 是否可能影响既有配置/数据 |
|---|---|---|---|---|
| P0 | 真人完整联调、协议与权限来源诊断 | 确定能收消息、确认、执行、交付 | 中 | 不需要破坏性迁移 |
| P1 | 执行日志、进度、失败定位与交付重试入口 | 看得见卡在哪里，能恢复丢失结果 | 中 | 追加表/接口，需 schema 版本 |
| P1 | 浏览器下载/上传/选项/会话恢复 | 完成文档、后台系统等真实网页任务 | 中 | 可追加工具参数，保留现有 profile |
| P1 | Windows 桌面执行器 | 操作浏览器以外的软件 | 高 | 独立适配，不替换 Codex 核心 |
| P1 | 持久化工作流与检查点 | 重启能从确认位置继续，避免重复发信/提交 | 高 | 增加任务数据模型与迁移 |
| P2 | 原生记忆查看/删除、历史检索性能 | 长期事实可纠正，旧对话检索更快 | 中 | 优先复用原生存储，不复制原文 |
| P2 | 额度、超时与无进展检测 | 防止单个任务无限尝试 | 中 | 增加上限；可能提前中断旧习惯 |
| P2 | 桌宠状态视图、开机自启、备份保留 | 日常使用和维护更方便 | 中 | 界面与服务分层，数据不绑桌宠 |
| P3 | STT/TTS、事件触发、额外通道与设备 | 扩展交互和主动协助 | 中到高 | 按需开启，增加依赖和授权 |

如果目标是“帮我操作电脑上的一切”，桌面适配必须较早做；只有网页自动化和命令执行，覆盖不了没有 API 的本地 GUI。但桌面适配的成熟度要按目标 Windows 驱动实际核对，不能把 macOS 的 Codex Computer Use 路径直接当作 Windows 现成方案。[官方平台与驱动限制](https://docs.openclaw.ai/plugins/codex-computer-use)

## 4. 各阶段怎么实现

### P0：让当前闭环可确认

保留固定 Codex/飞书 CLI 版本。启动读取原生 config layers 和实际 policy；CLI 使用项目登录目录。确认消息、回调、文件返回值和模型输入的契约都一致。真人联调清单见 [认证交接文档](device-auth.md)。这里没有将尚未联调的能力算作稳定产品能力。

### P1：执行与恢复

1. **执行记录**：保存任务、轮次、工具名、状态、耗时、脱敏错误和产物索引；原始密钥/网页会话不进日志。提供查看、取消和重新交付入口。
2. **浏览器**：浏览器 service 负责下载目录、文件上传、稳定 tab ID、导航结果与弹窗；工具只描述操作。下载结果走产物索引，不直接从浏览器 profile 暴露文件。
3. **桌面**：定义独立的 Desktop service，优先接已有 OS 自动化 MCP/驱动；先支持截图、窗口、输入、点击、快捷键。使用实际观察定位，保留确认与手动接管。不要在 Shell Tool 中堆截图/坐标逻辑。
4. **工作流**：先用有固定业务意义的步骤状态，保存输入摘要、结果和幂等键；已完成步骤不重复。未知外部结果进入“需人工核对”。允许本人显式恢复，不能自动重放任意 Agent 轮次。OpenClaw 的 Lobster 是可选插件，也需要启用，不是所有后台任务天然可恢复。[Lobster 确认与恢复](https://docs.openclaw.ai/tools/lobster)

验收目标：中断后能解释已做了哪些步骤、下一步是什么；不会把重新发同一句 prompt 冒充断点恢复。

### P2：记忆、资源与可用性

记忆与聊天历史优先复用 Codex 原生存储。下一步关注原生记忆的查看、删除、来源和费用可见性；将来确需跨线程正文检索时再设计，不重新保存第二份原文。OpenClaw 的混合检索需要 embedding provider；自动 memory flush 也可能引入额外模型轮次。[Memory](https://docs.openclaw.ai/concepts/memory)

原生 token usage 已有落库入口，下一步做按轮次/任务展示、预算提示、持续失败/无进展截止。会员额度不能用 token 数直接换算成精确余额。进程重连只能恢复线程和状态，是否重新执行必须结合外部操作记录。

桌宠已通过本机桌面通道复用 gpt-claw 的会话、确认和交付。下一步扩展同一通道的任务、原生历史、产物和连接状态视图；桌宠不直接使用 Codex JSON-RPC，也不持有飞书密钥。开机自启用 OS 原生管理；备份加入 schema/version 元数据；提供恢复前检查。

### P3：按需主动化

事件 watcher 接收本地文件变更、邮件等明确事件，先用确定性过滤/合并/去重，再决定是否启动模型；默认无 AI 心跳。定时/主动工作增加安静时段、通知节流和失败告警。OpenClaw 已有多类自动化和 webhook 入口，可参考其职责划分。[Automations](https://docs.openclaw.ai/automation/cron-jobs)

保持 Codex 为唯一 Agent 内核。模型服务切换仍通过现有 Codex 适配处理，并明确展示会话、权限及计费变化；不能在会员额度不足时悄悄改用付费 API。[Model failover](https://docs.openclaw.ai/concepts/model-failover)

## 5. 当前不默认建设的内容

多人/团队管理、复杂身份代理、默认定期 AI 心跳、全量对话自动写记忆、完整插件市场和跨设备集群没有列为个人 MVP 的必要范围。后续若有实际需求，按独立适配增加，不把这些边界重新塞回核心。

先补本人日常可执行、可观察、可恢复的能力，其他部分继续复用 Codex、现成 MCP 和明确的业务脚本。
