## 猫耳原型归档

## 设计决定

一个浮灵本体、一套桌面标记、一个可展开的对话面板，不制作分身。本体可以移动到目标软件边缘陪用户工作，标记准确指出按钮、文字范围或代码位置。

目标是有稳定性格、动作连续、懂得安静、能真正协助工作的桌面搭档，也是在桌面上有自己日常的小角色。它会散步、玩耍、发呆、休息，偶尔到正在使用的软件旁边看看，发现合适时机再问是否需要帮助。形象、语言、目光、标记与实际执行围绕同一件事，避免各自播放互不相干的效果。

## 历史猫耳方案：形象与性格

保留已认可的 A 猫耳小助手与圆头搭扣鞋设计，不因当前模型失败而更换角色风格。约三头身，奶油色蓬松短发、暖杏色短外套、深蓝点缀、琥珀眼睛和柔软蓬松尾巴。认可的角色图是美术目标，仍需真实模型验证。先做好桌面小尺寸下的脸、发型轮廓、表情和眼神，再扩展身体、服装与细节；头部、耳朵、身体姿态和尾巴是主要表达渠道。

性格以温和、能干、好奇、有一点俏皮为主。普通交流自然简短，遇到真正的问题认真说明依据。用户专注时安静；被叫到时及时回应；成功时短暂开心，失败时收敛并解释。不会为表现“有生命”而反复追问、索要注意或凭空描述用户情绪。

同一角色保持习惯，例如听人说话时稍微前倾，思考时短暂移开目光，发现目标时先看过去。语言中的语气与动画方向一致，但不用每句话都配一个夸张动作。

## 活动与动作

完整动作库按生活、移动、玩耍、互动、观察、工作、情绪和休息组织。首批优先精做能串成完整日常与协助过程的动作，随后逐步扩充；最终体验不以几个工作状态为范围。目光、眨眼、眉眼与嘴部表情、耳朵和尾巴变化叠加到身体动作上，复用精做素材。

动作遵循“先注意到 → 再反应 → 最后稳定下来”。看向软件后才移动，移动到边缘后调整姿态，得到真实结果后才反馈。动作之间平滑衔接；回答和任务被打断时能够收回动作。

本地驱动呼吸、眨眼、低频姿态变化、视线和移动过渡。主动陪伴开启后，低频模型判断可以选择合适的姿态或提出帮助；不为每次眨眼、转头、移动调用模型。待机小动作不声称它观察或理解了当前内容。

鼠标经过可以有轻微关注，单击打开对话，拖动调整位置。保留已有双击回复卡进入输入的操作。后续把轻抚、递玩具和挥手等角色互动接到专门的交互区域或明确入口，避免和打开对话、拖动冲突。不会自动追着鼠标跑，也不靠频繁音效维持存在感。

## 桌面生活与自娱自乐

| 日常 | 动作方向 | 一段完整行为 |
| --- | --- | --- |
| 安静陪伴 | 坐着晃腿、趴着、盘坐、看远处、整理衣角 | 选一个姿势待一会儿，观察四周，换个舒服的姿势继续待着 |
| 桌面散步 | 走、轻跑、转身、停步、沿外缘探头 | 起身去一个允许的位置，看看，停留一会儿再返回 |
| 自娱自乐 | 抛小球、拨光点、折纸、翻自己的小书、绕尾巴玩 | 拿出玩具、尝试、失手、看看玩具、捡回来、再玩一次，最后收好 |
| 好奇探索 | 歪头、耳朵竖起、凑近、坐下观察 | 在主动陪伴允许的目标旁停留，先观察，有帮助机会时才轻声提议 |
| 和用户互动 | 抬头、挥手、开心靠近、轻抚反馈、接住小玩具 | 被叫到后暂停玩耍，收好东西，朝用户转身并回应 |
| 工作陪伴 | 倾听、记笔记、认真看、思考、带路、短反馈 | 接到请求、移到合适位置、核实内容、说明与指路，完成后恢复日常 |
| 表情与小情绪 | 得意、疑惑、害羞、惊讶、挫败后重试、松一口气 | 玩具没接住时愣一下，确认任务成功后开心一下，出错时认真说明 |
| 休息 | 揉眼、打哈欠、伸懒腰、蜷缩、打盹、醒来 | 活动久了伸展一下，安静时打盹，被叫到时醒来并进入倾听 |

软件边缘的动作是本地覆盖层的视觉摆放，不改变软件布局；具体位置必须有空余空间。站、坐、趴、探头等选择与可用落点一致，不硬把身体塞进文字和按钮。玩具、书和纸等是角色自己的小道具，不读取或改变用户文件。

自娱自乐采用完整小片段，开始、展开、结束都有关系。不同片段之间有较长的稳定停留，不按固定间隔突然抽取一个大动作。动作变化可来自姿势、速度、视线、成功或失手等小差异，保持角色自己的习惯。

例如它在自己的位置玩小球，第一次没接住，看看滚到身旁的球，用脚轻轻拨回来，坐下再试；用户叫它时放下球、转头回应。当前有执行任务时不会突然开始玩耍；任务结束后可以短暂反馈，再选择之前的日常或新的休息姿势。

散步与空闲位置和帮助目标分别处理。桌面散步的目的地由本地可用空间选择，不需要识别软件内容，也不需要模型判断。要根据软件内容主动靠过去、提出建议，则必须开启主动陪伴并有有效共享授权。关闭共享后仍可进行普通待机和本地玩耍，但停止依赖工作内容的观察与跟随。

## 自主行为的连续性

本地保存角色的短期活动状态，例如目前在玩什么、刚完成什么、上次到过哪里、是否已经向用户提过同一建议。轻量的精力、好奇程度和当前关注对象用于选择动作，表达角色行为的连续性；它们不代表真实情绪或对用户心理的判断。

本地行为编排负责动作、道具、过渡、取消和等待；模型在主动陪伴下低频判断当前情境与下一段行为意图。模型只从受校验的行为目录选择，例如继续安静、到允许的窗口旁观察、玩一次小球、休息或提出帮助。本地检查当前状态、空间和授权后决定是否执行，不让模型生成任意动画代码或电脑操作。

用户请求、停止和手动拖动优先于日常。纯动画中断立即进入安全过渡；如果涉及原生模型轮次，则等待取消真正结束后再处理用户消息。任务期间保持工作动作，等待用户决定时安静，日常行为不会挤占执行队列。

默认生活节奏安静，允许一个简单的“更安静 / 更活泼”设置调节散步和玩耍频率。用户持续输入时减少大幅移动和主动开口；日常不自动展开面板或发出频繁声音。忽略一次帮助建议后，它可以自己回去玩或休息，不反复问同一个问题。

最终的生动感来自完整行为与自然停顿：它有可见的日常，有机会和用户互动，接到事情能立即认真起来，事情做完再回到自己的生活。

## 本体在桌面上的位置

本体有用户安排的默认位置。持续阅读、代码分析或引导操作时，可以移动到目标窗口边缘或附近空白处；简短提醒通常只转头并显示标记，不移动整个角色。自动移动可以关闭。

位置选择综合目标窗口边界、屏幕可用区域、当前操作目标和面板展开空间。优先避开文字、输入框、按钮和鼠标附近的操作区。没有合适空间时保留原位置并使用标记，不硬挤到内容上。覆盖层停靠于窗口边缘，不承诺能在所有软件里真正坐到其内部控件上。

同一任务期间保持停靠，具体目标变化主要由标记表达。跨窗口的连续任务只在确有必要时重新选位置；任务结束回到默认位置。用户拖动拥有优先权，更新默认位置并暂停当次自动跟随，不立即拉回。多屏、DPI 和窗口移动需要实际验证。

宠物只在可见形体和必要交互区域接收鼠标，不让整块透明矩形遮住软件。标记层鼠标穿透。面板自动选择可展开的一侧，移动和弹出不夺取输入焦点。

## 看、指路和操作

| 目的 | 本体 | 标记与结果 |
| --- | --- | --- |
| 找按钮或菜单 | 看向目标，长任务时停靠附近 | 柔和目标描边，必要时一句提示 |
| 阅读文档 | 安静坐着，解释时稍微前倾 | 细括线标出相关范围，按需展开解释 |
| 分析代码问题 | 停靠编辑器旁，认真观察 | 真实文件行号、问题说明、打开位置入口 |
| 带用户完成多步操作 | 保持陪伴位置，每步结束给轻反馈 | 只突出当前一步，必要时少量编号 |
| 代用户执行 | 专注，等待决定时停下工作动作 | 当前动作、停止入口，以及核实后的结果 |

标记准确性优先于装饰。截图定位使用最新观察与目标绑定，窗口移动、尺寸或内容变化后撤掉过期标记，重新核实再显示。正在阅读解释时不靠统一短计时器让内容消失；过期目标不能因为阅读尚未结束而继续显示。

代码问题先读取用户指定的源码、报错和日志，屏幕只提供线索。文件与行号由业务层校验，编辑器桥接负责打开位置；需要屏幕标注时再确定可见位置。“解释、定位、修改”分别由用户意图触发。电脑操作遵守共享授权、目标窗口检查和操作后观察，不能仅凭成功动画宣布完成。

## 一个对话空间

平时只显示宠物；短消息用小气泡。打开后成为对话面板，长内容或记录查阅时扩展同一个面板。当前对话、草稿和进行中的任务保留，查阅旧记录不等于恢复旧 Codex 线程。

普通回复没有“已完成”，没有固定的“复制”“追问”底栏。选中文字即可复制，双击卡片可继续输入。正文只保留真正有用的上下文动作，例如打开代码行、查看文件、定位目标。过程和消耗按需展开。

文字与语音进入同一桌面会话。语音动画跟随真实监听和播放，能打断后续输出；连续语音一分钟无输入回到待唤醒，生成和朗读时间不计入空闲。新角色上线前核实唤醒、欢迎与结束语音的现有实现，不把目标设计当成可用承诺。

## 有分寸的主动帮助

普通对话和仅开启共享屏幕都不触发周期模型调用。另行开启“主动陪伴”后，才低频观察选定工作应用，并允许保持安静、调整姿态或提出一条有依据的帮助提示。

例如看到清晰报错，先看向编辑器，在合适空白处停靠，再显示“这里有条报错，要一起看看吗？”的小提示；用户接受后重新核实，再解释、定位或按请求处理。也可以在用户允许的工作窗口旁安静陪一会儿，适时问一次是否需要帮助，没有具体线索时不声称发现问题。用户输入、录音、执行任务时跳过观察，不积压；同一问题被忽略后不反复提醒。停止共享、紧急停止、断线和会话切换撤回观察能力。

主动观察轮次必须由后端限制为只读，不能自主点击、修改代码或发送消息。用户明确要求处理后进入正常执行链。具体调度、调用上限、目标过滤、安静通道与同一 Codex 线程调度见交互方案。

用户指定的角色位置、音量、自动移动和主动陪伴配置由本地设置处理。当前工作情境是短期状态，不把连续截图、私人内容积累成业务长期记忆。稳定偏好只使用已有记录或明确设置；不能因为角色亲切就声称知道用户未提供的经历。

## 技术路线与资源

使用 PySide6 承接本地窗口、输入、语音与桌面协议，QML / Qt Quick 承接视觉与过渡，Qt Quick 3D 显示角色。当前以 QQuickWidget 嵌入现有 Qt Widgets 窗口，逐步迁移界面。正式角色制作源文件保留 Blender 工程，导出 glTF/GLB 并转换为 Qt 资源；部署模型、贴图与动画，避免按动作堆叠整幅逐帧图片。

前端把真实任务事件、语音生命周期和受校验的模型意图转成动作。标记与编辑器定位使用结构化目标；Codex 仍是唯一执行内核，宠物前端不另开一个模型会话。前后台工作遵守现有线程与任务边界。

漂亮程度取决于模型、表情、动作和小尺寸渲染的实际表现。B 样机与当前 A 简模证明 Python / Qt Quick 3D 路径可运行，不能证明完整 A 角色已经达到概念图质量。2026-10-13 的全身研究版已重做衣服、手与四肢，加入连续肩肘腕、髋膝踝节点，并验证散步、坐着玩球、前倾倾听和侧躺休息。它使用节点变换与姿态混合，尚无正式蒙皮、布料修形和完整脚底约束；实际对照见 [角色美术重做方案](minipet-character-art-direction.md)。正式资产继续以样片的脸部体积、蓬松发型、软外套和尾巴为标准，不能用动作数量替代美术验收。

### 正式角色的关节与变形设计

以下是下一份正式资产的制作要求，不代表当前研究版已经具备这些能力。

- 身体采用根节点、骨盆、腰、胸、颈、头的层级。根节点负责移动与整体朝向，骨盆负责站立、坐下和侧躺高度，腰胸分别控制倾听与伸展；头部可以继续看向用户或目标，不随身体机械转动。
- 双臂采用肩、上臂、前臂、手掌，双腿采用大腿、小腿、脚、脚尖。脚底约束用于支撑脚，手部目标用于托球、扶地和托腮；道具绑定手掌的固定挂点。普通引导采用摊掌与目光，精确位置交给桌面标记。
- 耳朵每侧预留二至三个控制段，尾巴预留五至七段；刘海只给少量有意义的发束增加轻微摆动。副动作跟随转头、走路与停步，不让所有部位持续同频摇晃。
- 眼球朝向、眨眼和表情独立控制。先做平静、好奇、思考、开心、疑惑、困倦六种神态，分别协调眉毛、眼睑、嘴和脸颊；开心闭眼与困倦闭眼使用不同眼睑弧线。
- 衣服与身体共用骨骼权重，肩肘、腰、髋膝的极端姿态增加修形。外套抬手时保留腋下体积，裙摆坐下时铺开，侧躺时顺着大腿收拢；不以刚性裙壳遮住腿，也不在过渡中突然替换整件衣服。

基础动作按完整片段制作：站立到迈步、迈步到停稳；站立到坐下、坐稳后托球；站立到前倾倾听、收回到站立；坐下到侧躺、闭眼休息、醒来再起身。表情与视线可叠加，脚底和扶地的手在接触阶段保持落点。每个片段至少检查正面、侧面及桌面小尺寸，特别检查膝肘接缝、衣服穿插、脚滑和道具脱手。

性能目标是日常伴随不影响工作。待机可降低更新频率，不可见或锁屏时暂停无用渲染；模型判断稀疏调度，资源规模和运行开销按实测调整。角色资产大小与 Python / Qt 环境大小分别评估，不承诺换成 3D 会消除整个目录的环境占用。

## 第一版与验收

第一版同时验证角色生活和真实协助：做出一段完整自娱自乐、一段散步或休息、被叫到时的自然响应，再加入可展开面板、本体移动停靠、目标标记、代码行定位、实际任务状态与停止。先把“自己玩一会儿 → 被叫到 → 看真实问题 → 去软件旁边 → 指出位置 → 解释或执行 → 核实结果 → 回到日常”跑通。主动陪伴在此基础上以独立开关加入；后续逐步扩大动作库与互动。

先用三个场景评价整机，而不是只展示动画数量：

- 用户连续工作十分钟：宠物有自然的日常活动与停顿，自娱自乐有开始和结束；不遮挡、不抢焦点、不反复说话，用户拖动后不会自动拉回。
- 用户提供一个真实代码错误：读取证据、说明原因、准确打开位置；屏幕指路使用有效目标，修改须有用户请求，反馈与真实执行一致。
- 用户开启主动陪伴后遇到报错：可以安静发现并给一次轻提示；忽略后不反复提醒，关闭后停止模型观察。

第三项属于后续主动陪伴验收，未实现时明确报告未验证。技术检查遵守工程 AGENTS.md；用户未要求时不新增或运行测试。
