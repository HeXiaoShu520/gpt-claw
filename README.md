# gpt-claw

部署在本人电脑上的个人助理。飞书和专属桌宠共用同一个 gpt-claw 服务；原生 Codex 是唯一 Agent 内核。工程提供确认卡、浏览器、个人记忆、后台任务、定时任务和 TypeScript 工具接入。

## 已实现的范围

| 能力 | 当前实现 |
|---|---|
| 飞书入口 | 长连接；只接受本人；群聊普通消息需 @机器人；消息 ID 去重 |
| 专属桌宠入口 | 同工程的 Qt 界面；聊天、流式回复、确认卡、图片显示、语音交互；“共享屏幕”默认关闭，开启后按请求截图并操作应用窗口；保留一次性“看看我在做什么” |
| 消息理解 | 文字、富文本、图片、附件、原生语音转写、合并转发、引用；卡片重新读取可见正文 |
| 人物身份 | 入口只接受本人；普通消息最多附本人姓名，缺少姓名就使用原文；真实提及和引用保留对应人物信息；回复使用原生卡片提及 |
| Codex | 原生线程恢复、CardKit 流式回复、执行状态、追加指令、中断、上下文压缩 |
| 权限 | 原生 `on-request` + `workspace-write`；整个工程是可写工作目录；工程外操作按需确认 |
| 浏览器 | 按需启动独立 Edge 配置；按会话隔离标签页；快照、点击、输入、按键、截图；点击和输入需要确认 |
| 记忆与历史 | Codex 原生线程管理完整上下文；桌宠保留界面展示记录；已成功发送的队列正文默认 7 天后清理。[存储分工与保留期限](docs/learning.md) |
| 后台/定时 | 独立线程、并发上限、持久化状态、结果回投；单次/间隔/cron |
| 扩展 | 原生 Skills / 外部 MCP；`tools/` 中的 TS 工具通过内置 MCP 暴露 |
| 可靠性 | 实例锁、SQLite 收件去重和发件重试；未执行的消息重启后恢复排队，运行中任务标记中断；Codex 意外退出后下次任务重连 |
| 启动引导 | 缺机器人凭证时扫码开通；检查工程内 lark-cli 的本人认证，未登录时扫码 |

当前是 MVP：桌宠已接入 Windows 截图、点击、键入、滚动、快捷键、拖动与应用切换，尚无 Web 控制台或完整工作流恢复。桌宠的语音识别和朗读需要在本地另配语音服务；它们不作为第二套 Agent 内核。卡片原文及人物资料仍取决于机器人权限和飞书接口返回。

浮灵桌宠现有27个运行时状态、16段基础Blender动画和23种连续活动。第一批改进已接入轻点/抚摸、困倦/睡眠/醒来、摆臂与撑手、手随球运动、可戳移动泡泡，以及忙时回应和真实任务结束反馈；松手掉落默认关闭。609张过程复拍、27张实际球轨迹复拍及19项交互检查见 [行为改进实施记录](docs/pet-behavior-implementation-2026-10-23.md)。肩肘细褶、精确接球和真实桌面接触仍待完成验收；此前惯性与轻音效见 [动作反馈实施记录](docs/pet-feedback-2026-10-23.md)。

对照6个桌宠项目的源码与实际资源，整理了106段动画清单和48项浮灵行为设计，见 [参考源码与动作设计](docs/pet-reference-review-2026-10-23.md)。第一批12项已接入，完成程度按实施记录逐项列出；其余36项仍为设计。

普通消息最多保留本人姓名；会话目录和共享屏幕说明不再逐条混入聊天正文。需要生成文件或查看本轮电脑共享状态时，模型按需调用只读 `personal.session_info`；闲聊不查询。实际附件与引用仍随消息提供，共享开关和操作校验继续由服务负责。修改后重启服务，用 `/new` 开新会话加载新的工具使用规则；旧记录保留。[上下文与授权边界](docs/architecture.md#三种权限边界)

混合桌面第一阶段已加入 Windows-MCP 控件观察、元素定位/宠物指示及条件等待。首次运行 `npm run computer:setup` 安装独立依赖，重启服务与桌宠后，在共享屏幕开启的当前请求中使用；纯截图功能不依赖此安装。当前已通过类型、构建和内部连接检查，真实软件操作效果尚待验收。[安装、用法、限制与后续计划](docs/computer-integration.md)

第二阶段已补静态状态文字、稳定控件身份和用户接管联动；独立真实窗口采集和桌面取消协议已验证。任务开始操作电脑后，真实鼠标/键盘输入会请求停止共享；继续需要重新开启共享并发送新请求。完整桌宠操作、指示和物理接管体验仍待验收。

当前处于“核心功能已实现、整体验收尚未完成”的阶段。基础版的完成标准、P0–P4 演进顺序与下一步工作统一见 [产品路线与验收标准](docs/roadmap.md)；未来增强项不等于当前已交付能力。

Codex 会话以整个工程根目录为工作目录。在 `workspace-write` 模式下，工程内常规文件读取、修改和命令可在沙箱内执行；项目已允许沙箱网络访问，供飞书 CLI 等工程内命令使用。工程外目录和 Codex 保护的 `.git/`、`.codex/` 等位置仍可能请求授权。`workspace/` 只存放收到的附件和生成的文件。WindowsApps 内的 MSIX PowerShell 无法在原生沙箱启动时也可能触发命令升级请求；工程在助理指令中指定使用系统 PowerShell，不改变系统 PATH。

## 安装与启动（Windows PowerShell）

需要 Node.js 22.16+。浏览器功能默认使用本机 Edge，不下载另一份 Chromium。

```powershell
Set-Location 'E:\源丶工程\gpt-claw'
npm ci
# 首次安装、尚无 .env 时复制；已有文件不要覆盖。
Copy-Item -LiteralPath '.env.example' -Destination '.env'
# 尚未登录 Codex 时才需要执行；已登录可跳过。
npm run codex:login
npm run start
```

服务和桌宠可以分别启动，也可以组合启动。在工程目录运行：

| 指令 | 启动内容 |
|---|---|
| `npm run start` | gpt-claw 服务（飞书和桌面通道）+ 桌宠界面 |
| `npm run start:claw` | 单独启动 gpt-claw 服务（Codex 内核、飞书和桌面通道） |
| `npm run start:pet` | 单独启动桌宠界面 |

`npm start` 与 `npm run start` 等效。分别启动时，在两个终端依次运行 `npm run start:claw` 和 `npm run start:pet`。桌宠也可先启动，服务就绪后会自动连接；关闭桌宠后，独立启动的服务继续运行。旧指令 `npm run start:desktop` 是 `npm run start:claw` 的别名，`npm run pet` 和 `npm run desktop:ui` 是 `npm run start:pet` 的别名。

组合启动也可双击工程根目录的 `启动 gpt-claw.cmd`，或运行：

```powershell
Set-Location 'E:\源丶工程\gpt-claw'
npm run start
```

`npm run start` 和 `npm run start:pet` 首次都会自动安装 Python 桌面依赖，可能需要下载较大的包。`npm run start` 会复用已经运行的 gpt-claw；如果服务由它启动，关闭桌宠时也会停止该服务。`npm run start` 和 `npm run start:claw` 都按正常流程启动飞书和桌面通道；首次需要扫码时，在终端完成认证。组合启动等待服务就绪后打开桌宠。两种入口共用服务的记忆、工具和权限；桌宠的聊天窗口、快捷输入与截图行动使用同一个本地持久会话。桌面连接只监听本机，随机令牌写在已忽略的 `data/desktop-connection.json`，每次启动轮换。[桌面使用说明](desktop/README.md)

`codex:login` 使用工程固定版本的 Codex 登录。ChatGPT 登录与 API Key 登录属于不同计费方式；可用模型和额度以账号实际状态为准。[官方认证说明](https://learn.chatgpt.com/docs/auth)

默认不填任何模型变量，沿用本机的 Codex 登录和原生模型配置。想改用 DeepSeek，在 `.env` 加这一行：

```ini
DEEPSEEK_API_KEY=填写DeepSeek的Key
```

本机原生推理档位若设为 `xhigh`，简单聊天也可能很慢。在本工程 `.env` 的 `MODEL_NAME` 和 `MODEL_EFFORT` 两行可明确指定模型与档位；留空分别继承 Codex 原生设置。比如只写 `MODEL_EFFORT=medium`，模型仍沿用原生设置，不修改用户级 Codex 配置。`/model` 可立即查看当前模型和档位。

长会话会显著增加每次请求的输入量。工程 `.codex/config.toml` 设置原生自动压缩阈值为 64,000 tokens；旧会话首次超过阈值时，会先整理历史再回答当前消息，这一次可能耗时，也可在飞书发送 `/compact` 手动整理。之后继续沿用同一会话的压缩摘要。服务启动后会在后台恢复最近的聊天会话，不发模型请求。终端会分别打印会话准备、模型执行和本轮 token 用量，便于定位慢在哪一步。原有的 Skills、MCP 和应用连接器配置仍按 Codex 原生配置加载。

想用 OpenAI API，改填 `MODEL_API_KEY=你的Key`。两个 Key 只选一个。DeepSeek 的默认地址和模型已内置；只有第三方 Responses 兼容服务需要再填 `MODEL_BASE_URL` 和 `MODEL_NAME`。API 模式按对应服务用量计费；Key 不进入命令参数或应用日志。系统环境变量优先于 `.env`，修改后需重启。[模型服务配置](docs/model-providers.md) · [DeepSeek 原生 Codex 接入](https://api-docs.deepseek.com/quick_start/agent_integrations/codex/)

`npm run doctor` 在配置了 Key 时只报告配置存在，不调用 API 校验有效性或额度。

首次使用 `npm run start` 或 `npm run start:claw` 启动 gpt-claw 时，依次完成：

1. `.env` 没有完整机器人凭证：终端展示二维码，创建/绑定飞书应用，凭证写回 `.env`。
2. 检查工程内 CLI 的应用绑定和用户认证；未登录时再展示用户授权二维码。
3. `FEISHU_ADMIN` 留空时，从终端授权结果绑定本人；已有值时必须与登录者一致。
4. 启动 Codex，检查工程配置是否加载，以及实际权限是否为 `on-request / user / workspace-write`。
5. 连接飞书。在私聊发消息；群聊普通消息需要 @机器人。

CLI 认证失败时，已配置本人的机器人可继续启动；未绑定本人时启动失败。机器人向导当前仅支持国内飞书。已有应用可手填 `FEISHU_APP_ID` / `FEISHU_APP_SECRET` / `FEISHU_ADMIN`，仍会检查工程内 CLI 登录。

机器人需要开启长连接事件 `im.message.receive_v1` 和卡片回调 `card.action.trigger`。Codex 内部创建或恢复线程时不发飞书消息；真正开始处理后才创建 CardKit 2.0 流式卡片并挂在原消息下。CardKit 不可用时回退普通卡片，最终结果由持久化投递队列收尾。回复页脚显示 Codex app-server 返回的会话模型；若本轮收到模型路由切换事件，则显示切换后的模型。确认卡独立显示请求原因、参数及操作按钮，决策后保留结果；工具参数预览隐藏常见密钥字段。扫码向导预置常用权限，实际生效范围以授权页面及应用后台为准。已有应用缺权限时不会仅因重启自动升级。[完整扫码说明](docs/device-auth.md)

生成图片由机器人直接投递当前聊天；不超过 10 MB 时发送图片消息，超过 10 MB、但不超过 30 MB 时改发文件。前台和后台任务都会根据实际交付结果报告成功或失败。

## 常用操作

| 命令 | 作用 |
|---|---|
| `/help` | 使用说明 |
| `/status` | 当前线程、运行状态、队列及本聊天的投递状态、失败投递编号 |
| `/model` | 立即查看当前模型、推理档位和服务类型，不调用模型；直接问“你现在是什么模型”也走此入口 |
| `/retry 投递编号` | 重投失败的回复，不重新执行原任务 |
| `/stop` | 请求中断当前对话任务、取消其待确认请求并清空队列；不能撤销已发生操作 |
| `/new` | 等待当前任务结束后切换新线程；旧原生历史仍保留 |
| `/compact` | 请求 Codex 原生上下文压缩 |
| `/steer 补充内容` | 给正在执行的任务追加指令 |
| `/jobs` / `/schedules` | 查看当前聊天的后台/定时任务 |
| `/answer 请求编号 回答` | 回答卡片中的自由文本问题 |

以上 11 条命令会在启动时同步到飞书原生 `/` 面板，处理逻辑和 `/help` 共用 `src/app/commands.ts` 清单。旧版 `/learn`、`/reflect`、`/recovery` 面板命令将在下次同步时移除，手动发送时只返回移除提示。点选后沿用 `im.message.receive_v1` 消息入口和本人身份检查；若飞书投递群聊中未 @机器人的已支持 `/` 命令，也会处理。群聊客户端的面板投递行为尚未实测。`/steer`、`/answer`、`/retry` 没有参数时显示填写方法。

同步使用机器人 SDK 和本应用凭证。缺失项创建，描述变化更新，一致项跳过；保留其他已注册项及图标。同步失败会提示错误，不阻断普通聊天。权限开通并发布后可运行 `npm run feishu:commands` 单独重试；客户端菜单可能需约 5 分钟刷新。[注册实现](src/feishu/slash-commands.ts)

可直接说：“打开这个网页……”“后台帮我整理……”“明天上午九点提醒我……”“把生成的文件发给我”。跨会话偏好由 Codex 原生记忆按空闲策略提炼，必须稳定生效的规则直接写入 `AGENTS.md`。助理选用工具后，服务会对浏览器点击和输入、创建任务等请求确认；确认卡不展示自由文本参数或原始 Shell 命令，以免在聊天中泄露凭证。发送 `workspace/` 内的文件到当前聊天无需二次确认，以飞书返回的消息 ID 为成功依据。后台任务需单独取消，`/stop` 不会取消其他任务。

## 配置与扩展入口

| 文件/目录 | 用途 |
|---|---|
| `.env` | 飞书凭证、本人 ID、模型选择、并发及超时 |
| `.codex/config.toml` | 原生 Codex 权限、记忆、搜索与外部 MCP |
| `AGENTS.md` | 工程根目录中的助理约束与“性格与说话方式”；编辑后重启服务，并使用 `/new` 开新会话后生效 |
| `.agents/skills/` | 原生 Skill；每个技能一个含 `SKILL.md` 的目录 |
| `tools/` | 本人安装的 TS/JS 工具；默认导出 `ToolSpec` |
| `data/` | SQLite 运行状态、人物缓存、CLI 登录、独立浏览器配置；旧版记忆文件暂保留 |
| `workspace/` | 按持久的文件会话 ID 分目录保存附件、截图和待交付文件（`workspace/{sessionId}/inbound/`、`workspace/{sessionId}/artifacts/`）；`/status` 可查看当前 `fileSessionId`，`/new` 切换到新目录。Codex 工作目录是工程根目录 |

项目配置需要项目发现与信任；原生配置也会继承本人的用户级设置。本工程以 `.codex` 标识项目根；首次需要信任时，通过原生配置接口在用户级配置中记录本工程根目录的 `trust_level=trusted`，保留其他配置。如果已有适用的 `untrusted` 决定，则停止启动。权限、Skills 和 MCP 配置仍保留在工程内。`GPT_CLAW_WORKSPACE` 仅控制附件与产物目录，不改变 Codex 的工程工作目录。[官方配置层说明](https://learn.chatgpt.com/docs/config-file/config-basic)

服务日志使用本机时区，显示为 `2026-09-28 02:40:00`。持久化时间仍使用时间戳或 UTC，不依赖日志显示格式。

终端会在消息归一化后打印本人的单行对话摘要，并在飞书投递成功后打印助理回复摘要。每条最多显示 500 字符；斜杠命令参数及常见密钥、链接、长标识会隐藏。模型对话由 Codex 原生线程保存，飞书保留原始聊天；终端摘要不包含 Codex 内部推理。

修改配置、提示、TS 工具后重启。扩展方法见 [Skills、TS Tool 与 MCP](docs/extensions.md)。

## 开发命令

```powershell
npm run dev          # 启动服务和桌宠；服务源码变动后自动重启服务
npm run dev:claw     # 仅启动服务并监听源码
npm run check        # 核心与 TS 工具类型检查
npm run build        # 构建核心服务
npm run start:built  # 构建后启动飞书和桌面服务；TS 工具仍由 tsx 加载
npm run doctor       # 本地配置/安装及 Codex 登录诊断，不执行模型任务
```

`dev` 与 `start` 启动相同的服务和桌宠界面；开发模式额外监听 `src/`、`tools/` 下的 TS/JSON 文件。源码变化后先停止本次启动的服务，再重新启动，桌宠保持打开并自动重连；断线会关闭共享屏幕，需要手动重新开启。修改 Python 界面、启动器、`.env` 或 Codex 配置后需要重新运行。开发模式复用已有服务时不会接管它，也不会为它启用监听，后端日志仍在原启动终端；需要监听时先在原终端停止该服务。终端分别打印启动模式、Python 环境、服务等待/复用、桌宠进程与连接及退出状态。

## 边界

- 内核接入是官方 **Codex app-server 的 stdio JSON-RPC**，依赖 `@openai/codex@0.157.1`；没有使用 `@openai/codex-sdk`。这是官方自定义客户端入口，目前官方也标注 app-server 命令的实验性质，升级需要核对协议。[官方 app-server 文档](https://learn.chatgpt.com/docs/app-server)
- 原生权限保护 Codex 的文件/命令执行。TS/MCP 服务作为独立进程内代码运行，不自动处于 Codex 沙箱里；需自己校验参数、绑定目标并确认副作用。
- 机器人消息、历史和文件发送使用机器人应用身份。CLI 使用 `data/lark-cli` 中本人授权的账号，不能把它当作机器人身份；没有单独的通用 CLI 业务工具。原生命令子进程也默认绑定此目录。CLI 命令明确使用 `--as user` 或 `--as bot`；结构化错误及可辨认的纯文本缺权限错误会触发相应补授权入口，无法辨认身份和 scope 时不会猜测。用户授权完成后需重试原请求。
- 单人、本机信任模型。删除环境变量和 `.gitignore` 不等于阻止模型读取所有本机文件；勿把凭证写入提示、工具结果或记忆。
- 无本工程的默认模型心跳。消息、本人要求的后台任务和到期定时任务会用模型；Codex 原生记忆可能在空闲时额外生成并消耗额度。
- 中断没有回滚保证；浏览器已经提交、外部工具已经发出的请求可能继续完成。尚未执行的消息重启后恢复排队；已进入执行的消息不会自动重放。`/status` 可查看当前队列、本聊天的投递统计与最早 20 条失败编号（`delivery.failed[].id`）；用 `/retry 编号` 只重投已失败的回复，不重跑任务。存在更多失败记录时会提示，再次查看可列出重投后的后续记录。新版桌宠对最终文本保存后确认，并按投递 ID 去重；飞书在网络结果不确定时仍可能重复消息。
- 当前只完成静态类型检查与构建，未完成真人扫码、飞书回调、模型审批及浏览器的整条链路验证。

桌宠的日常活动见 [浮灵的日常生活与互动设计](docs/pet-lifelike-behavior.md)：在“陪伴方式 → 一起玩”选择连续活动，或使用日常/活泼模式自动活动。包含附近散步、巡视、玩球、打盹和任务栏边散步、双手搭边看你、返回原位；任务栏互动目前支持底部常驻任务栏。窗口后探头、图标互动列为后续阶段。新增 8 组活动、日常与点播分组及后续 24 项姿态设计见 [动作扩展设计](docs/pet-action-expansion.md)；新增活动尚待连续播放验收。更新 Python 界面后重新启动桌宠。

右键“陪伴方式 → 动作反馈”可分别开关气泡与眩晕特效、轻音效和松手后掉落。默认保持悬浮；开启掉落后，拖动松手会按速度下落，落地缓冲，较重落地时短暂眩晕再恢复。安静、休息和语音会话期间不播放动作音；眩晕短句由本地界面显示，不调用模型、不写入聊天记录。[动作反馈的实现与验证范围](docs/pet-feedback-2026-10-23.md)

悬停浮灵显示“聊天 / 语音”，双击打开身旁的轻聊天，并可在同一窗口展开完整记录；单次右键提供分层功能菜单。聊天窗口采用浅紫阅读区与冰青状态条，思考进度不混入正文；关闭窗口保留草稿和进行中的回复。交互规则与实际 Qt 控件预览范围见 [桌宠交互方案](docs/minipet-interaction-design.md)。

可单击或来回轻抚头部触发回应，睡着时点击唤醒；玩球期间点击小球可一起玩。操作与 Qt 连续渲染记录见 [触摸与陪玩](docs/pet-companion-interactions.md)。

任务开始、等待确认、成功、失败和取消也会驱动浮灵回应，并与语音、指引和拖动统一调度。实现范围与连续 Qt 渲染记录见 [任务如何驱动桌宠](docs/pet-task-behavior.md)。
